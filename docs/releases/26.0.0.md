# Pawtropolis Tech 26.0.0

Prepared 2026-11-14 on branch `release/v26`. Nothing has been merged or deployed: the steps to do that are below.

This is the end-of-2026 release. It adds one command and cleans up a lot underneath. The full list is in [`CHANGELOG.md`](../../CHANGELOG.md), and the audit behind it, with everything that was deferred, is in [`MODERNIZATION_PLAN.md`](../../MODERNIZATION_PLAN.md).

## What you will notice

**`/investigate-artist`.** Run it inside a 2D artist verification ticket. It reads the whole ticket, fetches every image the applicant posted, runs reverse image lookups, looks at the applicant's history in the server, and asks Claude to rate the application against the handbook's own criteria. You get a private reply: an advisory score, a breakdown per criterion with the evidence, every lookup match with its link, flags, follow-up questions to ask, and what it could not determine.

- Only user IDs in `OWNER_IDS` can run it. Everyone else gets a one-line refusal.
- The reply is ephemeral and nothing is posted in the ticket.
- It never approves, denies, changes roles or messages the applicant. Stolen, traced and AI-made art cannot be detected reliably, so it gives indicators with reasoning, not a verdict.
- It cannot open videos or source files such as `.psd` and `.clip`. It lists them by name. Those are the proofs the workflow leans on most, so open them yourself.
- Two test runs on a real four-image ticket took 74 and 78 seconds and cost 0.17 and 0.18 USD. The footer of every report shows that run's cost and the month's total, and the command refuses to run once the month would pass `INVESTIGATE_MONTHLY_CAP_USD` (200 by default).

**Three security holes are closed.** Dashboard sessions could be forged with a hand-written cookie. A failed `/update banner` or `/update avatar` could print the GitHub bot token in a public channel. The bot's internal dashboard API listened on every network interface.

**Eleven reliability bugs are fixed.** The ones staff could have met: panic mode switching itself off after a restart, an applicant whose modmail could never be opened again, `/redeemreward` taking a ticket and then finding no artist, queued welcome messages lost on restart, and slash commands logged as timeouts while they were still working.

**Two numbers change.** Weekly active users in the Stats Observatory and the daily chart on Pulse were wrong, and now they are right. Expect weekly active users to go up and the daily chart to show real message counts instead of 1.

**Some things are faster.** The activity check in `/audit members` takes 0.3 seconds per 100 members instead of 13.7. The `/activity` heatmap query is two to three times faster. Encoding leaderboard and heatmap images no longer stalls the bot.

## Before you deploy

1. **Check Node on the host.** `ssh bash-ec2 node -v` must print 20.9.0 or newer, and so must the version PM2 runs the bot with (`ssh bash-ec2 "pm2 describe pawtropolis | grep -i 'node.js version'"`). sharp 0.35 will not load on anything older. This could not be checked from the build machine.
2. **Add the new keys to the host `.env`.**

   | Key                           | Needed                  | What it is                                                                                                                                    |
   | ----------------------------- | ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
   | `OWNER_IDS`                   | Yes, for the command    | Your Discord user ID. Comma-separated if there are several. Empty means the command refuses everyone.                                         |
   | `ANTHROPIC_API_KEY`           | Yes, for the assessment | The organization's Claude API key. Without it the command still gathers the ticket and runs the lookups, and says the assessment was skipped. |
   | `ANTHROPIC_WORKSPACE_ID`      | Yes, with this key      | The workspace ID (`wrkspc_...`). The key is not tied to one workspace, and the API rejects it without this.                                   |
   | `INVESTIGATE_MONTHLY_CAP_USD` | No                      | Monthly cap on this command's own spend. Default 200. 0 switches the command off.                                                             |
   | `INVESTIGATE_MODEL`           | No                      | Default `claude-opus-5-5`.                                                                                                                    |
   | `INVESTIGATE_MAX_IMAGES`      | No                      | Images analyzed per run, 1 to 20. Default 12.                                                                                                 |
   | `SAUCENAO_API_KEY`            | No                      | Free account at saucenao.com. Without it SauceNAO is skipped and the report says so.                                                          |
   | `E621_LOGIN`, `E621_API_KEY`  | No                      | Free e621 account. Without them e621 is skipped and the report says so.                                                                       |
   | `DASHBOARD_API_HOST`          | No                      | Leave it unset. Only set `0.0.0.0` if the dashboard ever runs on a different machine from the bot.                                            |

   The host `.env` may already have an older `ANTHROPIC_API_KEY` that the research scripts used. Replace it with the organization key.

3. **Decide about the two held changes.** They are not in this release. Each is one commit on its own branch on top of it: `hold/v26-one-open-ticket-per-type` and `hold/v26-untrack-playwright-mcp`. See `MODERNIZATION_PLAN.md`, section 7, items 12 and 13.

## Release steps

```bash
# 1. Push the branch and wait for CI. CI has never run on this branch, and a
#    push to release/** starts it without touching main or the dashboard
#    deploy. Go on when all jobs are green.
git push -u origin release/v26

# 2. Merge. The push also starts the dashboard deploy workflow on GitHub,
#    because docs/ and web/ changed. Watch it, and let it finish before step 3
#    so two deploys do not run at once.
git checkout main
git merge --no-ff release/v26
git push origin main

# 3. Deploy the bot and the dashboard. The script backs up the database
#    first; that is its default.
./deploy.sh
```

The deploy script runs the tests, builds, uploads, installs, runs migration 084 (it only adds two tables), registers the slash commands and restarts PM2. If it prints `WARNING: Command registration failed`, run this on the host:

```bash
cd /home/ubuntu/pawtropolis-tech && npm run deploy:cmds
```

Then:

4. In Discord, type `/investigate-artist` in a 2D artist ticket. The command is registered for members with Administrator. If you do not see it, allow it for yourself under Server Settings, Integrations, on the bot's entry.
5. Run it once on a ticket you already know well, and compare the report with your own read.
6. Open the dashboard and do something that calls the bot, such as a config change. This checks the loopback bind. If it fails, set `DASHBOARD_API_HOST=0.0.0.0` in the host `.env` and restart the bot.
7. Run `/sync-tasks` so GitHub Issues match the todo files. The nine v26 todos (#00279 to #00287) were never mirrored, because that writes to GitHub: the sync creates six of them closed and three open.
8. Close `todo/00285.md` once you are happy with it in production.

## If something goes wrong

- **Dashboard actions fail after the deploy:** `DASHBOARD_API_HOST=0.0.0.0`, then `pm2 restart pawtropolis`.
- **The bot does not start and the log mentions sharp or canvas:** the host Node is older than 20.9.0. Upgrade Node or redeploy `main` as it was before the merge.
- **Rolling back:** redeploy the previous `main`. Migration 084 only added two tables, and the older code ignores them, so the database does not need to be restored.

## What was not verified

- `/investigate-artist` has never run as a real Discord command. There is no test server, so it was tested with mocks and with two local runs that read a real ticket and printed the report to a file. Its first run in production is its first run in Discord.
- SauceNAO and e621 have never returned a real match, because no keys exist yet.
- CI has not run on GitHub. Nothing was pushed. Its steps were replayed in clean clones under Node 24.22.3 and Node 20.20.2 and pass there, but that was on Windows and the runners are Linux. Step 1 of the release steps closes this.
- The production Node version.
- A real `git push` through the new token handling in `/update banner` and `/update avatar`. It is covered by unit tests only.
