
### Deploy Options

```bash

./deploy.sh --status     # Check remote PM2 status
./deploy.sh --logs       # Show logs after deploy
./deploy.sh --fast --logs # Deploy without tests + show logs
```

### What deploy.sh Does (9 Steps)

1. Run tests (`npm test`) - skipped with `--fast`
2. Build (`npm run build` via tsup)
3. Inject build metadata (`scripts/inject-build-info.ts` → `.env.build`)
4. Create tarball (`dist/`, `migrations/`, `scripts/`, `package.json`, `package-lock.json`, `.env.build`)
5. Upload tarball via SCP to `pawtropolis:/home/ubuntu/pawtropolis-tech/`
6. Extract + `npm ci --omit=dev` on remote
7. Run migrations (`node scripts/migrate-remote.js`)
8. Register slash commands with Discord
9. Restart PM2 + health check + cleanup

## Database Management

### Database Sync

- **Default**: Always pulls remote DB → local (never pushes unless `--push-remote`)
- **Backups**: Timestamped before any sync: `data/backups/data-TIMESTAMP.{local|remote}.db`
- **Integrity**: Verified via `scripts/verify-db-integrity.js`
- **Manifest**: Written to `data/.db-manifest.json`
- **WAL Checkpoint**: Performed before sync for consistency

```bash
./scripts/start.sh --push-remote        # Explicit push local → remote (stops PM2 first)
```

### Migrations


Migrations run automatically during deployment (step 7). Each migration runs in a transaction (all-or-nothing). Tracked in `schema_migrations` table.

## Code Patterns

### Adding a New Command

1. Create file in `src/commands/` (or subdirectory for subcommands)
2. Export a `SlashCommandBuilder` definition
3. Register in `src/commands/registry.ts`
4. Add handler routing in `src/index.ts` if needed
5. Run `npm run deploy:cmds` to register with Discord

See: `docs/reference/command-checklist.md` and `docs/reference/command-patterns.md`

### Feature Module Pattern

Each feature is self-contained in `src/features/` with:
- `index.ts` - Main module / barrel export
- `types.ts` - TypeScript type definitions
- `queries.ts` - Database queries (prepared statements)
- `handlers.ts` - Event/interaction handlers
- Optional subdirectories for flows, handlers, etc.

Features import `db` and `lib` modules but should not import other features directly.

### Error Handling

All command and event handlers are wrapped with:
- `wrapEvent()` - Consistent error handling, Sentry breadcrumbs
- Error cards displayed to users on failure
- Uncaught exceptions/rejections caught globally

### Configuration

- **Zod validation** at startup (`src/lib/env.ts`) - fail-fast on missing required vars
- **Per-guild config** stored in `guild_config` table
- **Feature flags** via database-driven toggles

## Troubleshooting

### Common Issues

| Issue | Solution |
|-------|----------|
| Commands not appearing | Run `npm run deploy:cmds` |
| Database locked | Stop other node processes, checkpoint WAL |
| SSH connection fails | Check `~/.ssh/config` and key permissions (600) |
| Port already in use | Run `./scripts/start.sh --stop` |
| Build fails | Clear `dist/`, rebuild with `npm run build` |
| Tests fail | Run `npm run check` for full diagnostics |
