# #00040 -- Validate Litestream configuration in CI / pre-deploy

**Type:** chore | **Priority:** Low | **Status:** `COMPLETE 2026-05-19`

Litestream R2 backup config lives in .env.example but CI does not check presence. A missing env var on prod silently disables replication.

**Resolution (2026-05-19):** Added `check_litestream_status` helper to deploy.sh (commit 536e093). Pre-deploy hook runs on bot-only deploys and full deploys (skipped for web-only). Logic via `systemctl is-active litestream`:
- active -> log healthy
- not-configured -> log neutral (no systemd unit; manual backup is the only safety net)
- ssh-failed -> skip silently
- other status -> WARNING with troubleshooting hint

Better approach than the original "check env vars" plan: Litestream actually consumes /etc/litestream.yml on the remote, not the bot's .env. systemd status is the real source of truth for "is replication running".

Action:
1. Add a script that validates required Litestream env vars (LITESTREAM_*).
2. Wire the script into deploy.sh as a pre-deploy check.
3. Optionally add a CI step that fails the build if .env.example is missing a Litestream var that production needs.
4. Log a warning at startup if Litestream is configured but not running.
