# #00113 -- ManageRoles Scope Warning reports role.position as the count of manageable roles

**Type:** bug | **Priority:** Medium

The issue text reads `Role can assign/remove ${role.position} roles below it.` but role.position is the hierarchy position index, not the number of roles beneath this one. The code computes `rolesAbove` (line 369) but never computes a roles-below count, then substitutes the position integer as if it were that count. Example: a staff role at position 50 with only 3 roles beneath it will tell moderators it can assign/remove 50 roles. This is misinformation inside a security advisory generated by `/audit security` (CONFLICTS.md) and shown to leadership, undermining trust in the audit and potentially causing wrong remediation decisions. Detection of the issue itself is fine; only the reported number is wrong.

**Location:** `src/features/serverAudit/analyze.ts:377`
**Category:** correctness | **Confidence:** high | **Audit severity:** medium (adversarially confirmed)

**Suggested fix:** Compute the actual count, e.g. `const rolesBelow = roles.filter((r) => r.position < role.position && r.name !== '@everyone').length;` and interpolate `${rolesBelow}` instead of `${role.position}` in the issue string.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0108. See audit/2026-05-31/full-codebase-audit.md.
