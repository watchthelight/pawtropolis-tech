# #00280 -- v26 security fixes: forged dashboard sessions, GitHub token leak, dashboard API exposure

**Type:** security | **Priority:** Critical

From the v26 audit (`MODERNIZATION_PLAN.md` section 3).

- SEC-1: `web/src/lib/server/session.ts` accepts a plain JSON cookie when decryption fails, so a session can be forged.
- SEC-2: a failed `git push` in `/update banner`, `/update avatar` and the server audit docs job puts the GitHub bot token into a public reply and the logs.
- SEC-3: the internal dashboard API listens on all interfaces and compares its secret with `!==`.
- SEC-8: workflows have no `permissions:` block and one third-party action is pinned by tag.

**Resolution (2026-11-14, 26.0.0):** all four fixed, each with tests where code changed. A session cookie that does not decrypt gives no session, so anyone holding a pre-encryption cookie signs in again. The GitHub token reaches git through an environment-supplied header and a failed push shows a fixed message. The dashboard API binds to `127.0.0.1` unless `DASHBOARD_API_HOST` says otherwise, and compares its secret in constant time. Workflows read the repo with `contents: read` and the gist action is pinned to a commit. Rotating `GITHUB_BOT_TOKEN` is an owner decision (#00287).
