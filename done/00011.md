# #00011 -- Refactor src/features/gate.ts (1602 lines) into a state machine

**Type:** refactor | **Priority:** High

gate.ts implements /gate command + its modals (handleStartButton, handleGateModalSubmit, handleDoneButton). Handlers share duplicated state checks and inline tier-progression logic. Hard to change one step without understanding the entire flow.

Action:
1. Define explicit states: StartPending -> GateSubmitted -> Done -> Cleanup.
2. Create src/features/gate/flow.ts with the state machine.
3. Move each handler to src/features/gate/handlers/<name>.ts.
4. Shared validation in gate/shared.ts.
5. Main gate.ts becomes ~200 lines (command registration + state machine wiring).
6. Add tests for flow transitions independent of Discord.

**Evidence:** audit/2026-05-19/code-quality-findings.md (Finding 5)

**Resolution (2026-05-27):** gate.ts reduced 1602 -> 28 lines (a pure re-export barrel). The status lifecycle is now an explicit, Discord-independent state machine in src/features/gate/flow.ts: the ApplicationStatus union, ACTIVE_STATUSES / TERMINAL_STATUSES sets, predicates (isDraft, isSubmitted, isActiveStatus, isTerminalStatus), the GATE_TRANSITIONS table + canTransition, and classifyDraftStatus. handlers.ts now branches on classifyDraftStatus instead of inline status string checks (no behavior change). Interaction handlers live in gate/handlers.ts and ensureGateEntry moved to gate/entryPanel.ts alongside the rest of the panel-management code; shared concerns are split by purpose across flow.ts / ui.ts / drafts.ts / entryPanel.ts rather than a single shared.ts. Added tests/features/gate/flow.test.ts (20 transition/predicate tests, no Discord), and replaced the inline status reimplementations in gate.test.ts with real flow imports. Full suite green (5411 pass). Commits c3e79d0, fceb889, 2457920. Gap vs action item 3: handlers were consolidated into one gate/handlers.ts rather than a per-handler handlers/<name>.ts subdir; the single file is small and cohesive, so a further split was judged unnecessary.
