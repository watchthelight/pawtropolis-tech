# #00232 -- `expect.any(Number)` misused as a mock return value, not an assertion

**Type:** bug | **Priority:** Low

The test "uses current timestamp when joinedAt not provided" passes an asymmetric matcher (`expect.any(Number)`) inside `mockGet.mockReturnValueOnce({ joined_at: expect.any(Number), flagged_at: expect.any(Number), ... })`. `expect.any(...)` only has meaning inside an `expect(...).toEqual(...)`/`toHaveBeenCalledWith(...)` comparison; used as raw data it just stores a matcher object on the returned row. The test never asserts on `result` (the variable is assigned on line 245 but unused), and only checks `expect(mockRun).toHaveBeenCalled()`. So the intended verification (that `now` is used for joined_at/flagged_at when joinedAt is omitted) is not actually performed - the test would pass even if the source forwarded the wrong values. No production impact; it is a weak/ineffective test.

**Location:** `tests/store/flagsStore.test.ts:232-254`
**Category:** test-quality | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Assert on the real call: capture `insertManualFlagStmt().run` arguments and assert `expect(mockRun).toHaveBeenCalledWith('guild-123','user-456', expect.any(Number), expect.any(Number), 'No join date', 'mod-789')`, verifying joined_at === flagged_at === a recent epoch. Remove the matcher from the mock return object.
