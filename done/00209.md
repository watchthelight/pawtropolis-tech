# #00209 -- Scheduler-health assertions are guarded by `if (schedulersField)`, so the test passes vacuously if the field d

**Type:** refactor | **Priority:** Low

The test 'shows scheduler status when schedulers are tracked' mocks getSchedulerHealth() to return a 2-entry Map, then locates the embed field named 'Schedulers' and only runs its expect() calls inside `if (schedulersField) { ... }`. If a regression in src/commands/health.ts caused the Schedulers field to stop being emitted (e.g., the `if (schedulerHealthMap.size > 0)` block were removed or the field renamed), `schedulersField` would be undefined, the if-block would be skipped, and the test would still report PASS with zero assertions executed. The test therefore does not actually protect the behavior it is named for. (It happens to run the assertions today only because the current implementation does emit the field.)

**Location:** `tests/commands/health.test.ts:218-221`
**Category:** dead-code | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Assert the field exists before inspecting it: `expect(schedulersField).toBeDefined();` then drop the `if` guard and assert `schedulersField.value` contains 'modMetrics' and 'opsHealth' unconditionally. Optionally also assert the WARN/failure formatting for the opsHealth entry (consecutiveFailures: 2).
