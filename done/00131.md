# #00131 -- Entire 'modals' suite never imports or executes the module under test (tautological tests)

**Type:** refactor | **Priority:** Medium

The file is named/structured as tests for the review modal submission handlers (handleRejectModal, handleAcceptModal, handlePermRejectModal, handleKickModal, handleUnclaimModal) in src/features/review/handlers/modals.ts, and it sets up vi.mock for logger/sentry/cmdWrap as if it will drive that module. But it imports NOTHING from modals.ts. Every single 'it' block re-implements the logic inline (e.g. `reasonRaw.trim().slice(0,500)`, regex literals re-declared locally, `customId` string templates) and asserts on those local re-implementations. Concrete impact: a real regression in modals.ts (wrong field id, missing trim/slice, wrong action dispatch, removed staff check, dropped deferUpdate) would NOT fail this suite - it provides false coverage. The describe blocks 'action dispatching', 'staff validation', 'application resolution' assert hard-coded booleans/strings (`expect(checkPerformed).toBe(true)`, `expect(action).toBe('runRejectAction')`) that can never fail.

**Location:** `tests/features/review/handlers/modals.test.ts:27-380`
**Category:** dead-code | **Confidence:** high | **Audit severity:** medium (adversarially confirmed)

**Suggested fix:** Import the actual handlers from src/features/review/handlers/modals.js and invoke them with a mocked ModalSubmitInteraction (fields.getTextInputValue, deferUpdate, customId, user.id, inGuild). Assert that resolveApplication/runRejectAction/etc. (mocked) are called with the parsed code and trimmed/truncated reason, and that non-matching customIds early-return. Delete the assert-a-literal tests.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0206. See audit/2026-05-31/full-codebase-audit.md.
