# #00255 -- detectNsfwFlagSurge filters nsfw_flags.flagged_at via strftime(), bypassing the guild/reviewed index

**Type:** bug | **Priority:** Low

detectNsfwFlagSurge runs two counts of the form `SELECT COUNT(*) FROM nsfw_flags WHERE guild_id = ? AND strftime('%s', flagged_at) >= ? AND strftime('%s', flagged_at) < ?`. nsfw_flags.flagged_at is declared `TEXT NOT NULL DEFAULT (datetime('now'))` (migrations/032_nsfw_flags.ts:45) and the only indexes are idx_nsfw_flags_guild(guild_id) and idx_nsfw_flags_pending(guild_id, reviewed) (lines 53-54). Wrapping flagged_at in strftime() makes the time bound non-sargable, so after the guild_id prefix narrows the set SQLite still scans every flag row for that guild and recomputes strftime per row. Bounded in practice: nsfw_flags has UNIQUE(guild_id, user_id) so row count is capped near member count, and the Pulse bundle is cached. Real but low impact.

**Location:** `web/src/lib/server/queries/pulse.ts:1211-1240`
**Category:** Performance / missing-index (non-sargable predicate) | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Compare flagged_at as a raw ISO string against JS-computed ISO bounds (`flagged_at >= ?`) so an index on nsfw_flags(guild_id, flagged_at) can seek, or store flagged_at as unix-seconds INTEGER. Mirrors the modmail fix.
