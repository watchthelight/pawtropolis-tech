# #00106 -- /stats history export produces a download link to a non-existent /exports/ route (always 404)

**Type:** refactor | **Priority:** Medium

When export:true is passed, the handler writes the CSV to data/exports/<file>.csv and then surfaces a link `${process.env.PUBLIC_URL || "https://pawtropolis.tech"}/exports/<filename>` to the moderator, labeled "Download CSV ... Link expires in 24 hours". I grepped the bot's web bootstrap (src/startup/web.ts, src/web/dashboardApi.ts) and the entire SvelteKit route tree (web/src/routes). There is no route, static handler, or @fastify/static mount that serves `/exports/...`. The only export endpoint is web/src/routes/api/export/+server.ts, which generates its CSV inline from action_log and never reads data/exports. So every link rendered by this feature resolves to a 404 - the export is effectively unusable; the file is written to disk but can never be downloaded.

**Location:** `src/commands/stats/history.ts:269-274`
**Category:** dead-code | **Confidence:** high | **Audit severity:** medium (adversarially confirmed)

**Suggested fix:** Either (a) attach the generated CSV directly to the editReply via AttachmentBuilder (as /stats export in export.ts already does) instead of writing to disk and linking, or (b) add a real authenticated `/exports/:filename` route that serves files from data/exports with path-traversal protection. Option (a) is simpler and removes the disk dependency entirely.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0060. See audit/2026-05-31/full-codebase-audit.md.
