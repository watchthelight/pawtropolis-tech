# #00108 -- DB row inserted before role grant; if role grant fails the user is permanently locked out and falsely told the

**Type:** bug | **Priority:** Medium

The INSERT into verified_users (line 196-198) commits BEFORE the role is added (lines 206-217). If `member.roles.add(VERIFIED_ROLE_ID)` throws (missing Manage Roles perm, role above bot in hierarchy, transient API error), the error is caught and only logged (line 215-216); roleGranted stays false but the DB row already exists. On any subsequent `/verify`, the existing-row check (line 69) short-circuits and tells the user 'You have the Thin Line role' (line 78) - which is false - and never retries the role grant. Result: a user whose role-add failed can never obtain the Thin Line role through this command. The log embed even records 'Role Granted: Failed' (line 233), confirming the path is expected to occur.

**Location:** `src/commands/verify.ts:69-81, 195-219`
**Category:** data-integrity | **Confidence:** high | **Audit severity:** medium (adversarially confirmed)

**Suggested fix:** Either (a) grant the role first and only INSERT after a confirmed grant, or (b) in the existing-row branch, re-check member.roles.cache.has(VERIFIED_ROLE_ID) and re-attempt the grant if the role is missing rather than asserting the user already has it.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0064. See audit/2026-05-31/full-codebase-audit.md.
