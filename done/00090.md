# #00090 -- Copy-swap re-runs strftime('%s', created_at) on already-INTEGER epoch values, corrupting every timestamp

**Type:** bug | **Priority:** Medium

needsMigration() returns true if ANY of {CHECK present, created_at!=INTEGER, FK!=CASCADE, missing idx_review_action_app_time} holds (line 86). Unlike migration 028 (which early-returns the moment created_at is already INTEGER), this script has NO such guard: if the table is otherwise fully correct (created_at already INTEGER Unix epoch) but merely lacks the idx_review_action_app_time index or has a non-CASCADE FK, runMigration() still executes the full copy-swap. The INSERT...SELECT then applies CAST(strftime('%s', created_at) AS INTEGER) to the already-INTEGER epoch column (lines 128-135). I verified in better-sqlite3 that strftime('%s', 1700000000) does NOT return NULL - it treats the integer as a date-ish numeric and returns garbage (e.g. 1700000000 -> 1780244213, ~year 2026), so COALESCE keeps the corrupted value. Result: running this 'repair' on a healthy DB that is only missing an index silently rewrites EVERY review_action.created_at to a bogus timestamp, destroying the audit trail's chronology and breaking idx_review_action_app_time ordering / time-range analytics. The transaction's only integrity check is row COUNT (lines 143-145), which still matches, so the corruption passes undetected.

**Location:** `scripts/fix-review-action.cjs:62-87, 117-137`
**Category:** data-integrity | **Confidence:** high | **Audit severity:** medium (adversarially confirmed)

**Suggested fix:** Mirror migration 028's guard: in needsMigration(), if getCreatedAtType()==='INTEGER', do NOT trigger the destructive copy-swap solely for a missing index or FK fix - instead create the index / rebuild only when a real schema (CHECK or TEXT created_at) problem exists, and add the index via a plain CREATE INDEX when that is the only deficiency. Equivalently, in the INSERT...SELECT only apply strftime conversion when the source created_at type is TEXT; when it is already INTEGER, copy created_at verbatim.
