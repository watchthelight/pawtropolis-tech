# #00043 -- Tests for web/src/routes/api/sse/+server.ts

**Type:** chore | **Priority:** Medium

Split from #00012 slice 1. The SSE handler is stateful: it opens a ReadableStream, registers a client in a global Map, sets a 30s heartbeat interval, and subscribes to an event bus at module load. Testing it needs a different harness than the other +server.ts handlers.

Action:
1. Use `vi.useFakeTimers()` to drive heartbeat ticks deterministically.
2. Mock the `fan-out` module (`addClient`, `removeClient`, `generateClientId`) so the global client Map isn't mutated.
3. Cases to cover:
   - 401 when locals.user absent.
   - 200 returns a ReadableStream with `text/event-stream` Content-Type.
   - Initial open registers a client (addClient called once with tier-filtered consumer).
   - Heartbeat fires every 30s (advance timers, assert chunk written).
   - Stream cancel path: removeClient called, heartbeat interval cleared.
4. Reuse `tests/web/_helpers/requestEvent.ts` for the event stub.

**Why not slice 1**: ReadableStream lifecycle is the brittle part. Mixing it with the simpler bot-API-passthrough tests would have hidden either kind of regression behind the other. Separating keeps each test file fast to read and fix.

**Evidence:** issue #00012; routes inspected 2026-05-20.
