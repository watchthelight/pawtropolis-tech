# #00238 -- Cleanup interval is never unref'd or cleared (inconsistent with every other scheduler/limiter)

**Type:** bug | **Priority:** Low

`setInterval(cleanupOldCooldowns, CLEANUP_INTERVAL_MS)` at module load is neither stored, `.unref()`'d, nor cleared on shutdown. Every other interval in this codebase (notifyLimiter, traceStore, all src/scheduler/* schedulers, badge live updates, dmVerification, movieNight) is explicitly `.unref()`'d and most expose a stop/destroy. The code comment even acknowledges 'This interval is never cleared'. Functional impact in production is small because gracefulShutdown calls `process.exit(0)` explicitly, but: (a) it keeps the event loop alive, so if the explicit exit path is ever bypassed the process will not exit on its own; and (b) it leaks the timer in tests/embedding scenarios that import this module (the very hang the comment warns about). It is the one outlier from an otherwise consistent, leak-safe pattern.

**Location:** `src/lib/rateLimiter.ts:149`
**Category:** leak | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Capture the handle (`const cleanupTimer = setInterval(...)`), call `cleanupTimer.unref()`, and export a `stopRateLimiterCleanup()` that does `clearInterval`. Optionally wire that into the gracefulShutdown cleanup block in src/startup/ready.ts alongside the other limiter teardowns.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0259. See audit/2026-05-31/full-codebase-audit.md.
