# #00148 -- safeShowModal dead-ends the user (no ack, no message) past the 2500ms token boundary; caller ignores the false

**Type:** bug | **Priority:** Medium

safeShowModal returns false (a) if the interaction is already acked, (b) if Date.now()-createdTimestamp > 2500ms, or (c) if showModal throws - and in cases (b)/(c) it sends NO user-facing feedback and performs NO acknowledgement. handleReviewButton (buttons.ts) calls openRejectModal/openAcceptModal/openKickModal/openUnclaimModal/openVoteOutModal which call safeShowModal, and NONE of these call sites inspect the boolean return. For reject/accept/kick/unclaim the button path runs resolveApplication (two synchronous SQLite lookups) BEFORE reaching safeShowModal; under DB lock contention (the codebase elsewhere retries SQLITE_BUSY, see dmVerification.ts:378-389) or event-loop pressure the interaction can cross 2500ms, after which safeShowModal silently bails and the moderator's click resolves to Discord's generic 'This interaction failed' with no modal, no ephemeral error, and no logged trace surfaced to them. Because the interaction was never acked, no error card fires either. This is a cross-file trust gap: buttons.ts trusts safeShowModal to either show the modal or surface a failure, but safeShowModal's contract is 'return false and stay silent'.

**Location:** `src/features/review/handlers/helpers.ts:138-166, 144-149 (buttons.ts)`
**Category:** ack-window | **Confidence:** medium | **Audit severity:** medium (adversarially confirmed)

**Suggested fix:** Have safeShowModal's caller act on the false return: when it returns false and the interaction is still unacked, send an ephemeral reply ('That action timed out, click again.'). Alternatively move the resolveApplication DB work to AFTER showModal where possible, since showModal needs the fresh token most; for reject/accept the app existence can be revalidated in the modal-submit handler (which it already is via resolveApplication).

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0324. See audit/2026-05-31/full-codebase-audit.md.
