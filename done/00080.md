# #00080 -- Wrong/missing DB_PATH silently creates an empty DB, 'backs it up', and migrates the empty file

**Type:** bug | **Priority:** High

The DB is opened with `new Database(dbPath, { fileMustExist: false })` (line 50) - the in-file comment at 48-49 even warns 'we'll happily create a fresh DB if the path is wrong. You'll only notice when all your data is mysteriously gone.' createBackup() (line 142) then does `copyFileSync(dbPath, backupPath)` AFTER the connection already created the file, so the backup is of the freshly-created empty DB, not the real data. All pending migrations then 'succeed' against the empty DB and get stamped into schema_migrations. On the server this is reachable: if DB_PATH in the remote .env is wrong, or the deploy extracts into a path where ./data/data.db doesn't yet exist (relative cwd mismatch), the bot boots against an empty database with a clean migration log and no recoverable pre-state. There is no assertion that the DB existed and was non-empty before migrating.

**Location:** `scripts/migrate.ts:48-56,134-143`
**Category:** data-loss | **Confidence:** high | **Audit severity:** high (adversarially confirmed)

**Suggested fix:** Open with `fileMustExist: true` for the migrate path (or stat the file before opening and abort if it is missing/zero-bytes when not explicitly bootstrapping). Take the backup via the filesystem BEFORE opening the connection, and skip/abort backup if the source does not exist instead of copying a just-created empty file. Gate fresh-DB creation behind an explicit `--init`/`--bootstrap` flag.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0291. See audit/2026-05-31/full-codebase-audit.md.
