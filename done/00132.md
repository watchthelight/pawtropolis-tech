# #00132 -- isStaff / requireInteractionStaff / resolveApplication tests never call the real functions

**Type:** refactor | **Priority:** Medium

The describe blocks for isStaff, requireInteractionStaff and resolveApplication do not import or call those functions from src/features/review/handlers/helpers.ts. They instead call the mocked primitives directly (e.g. `hasRole(member,'gatekeeper-role-id')`, `findAppByShortCode(...)`, `loadApplication(...)`) and assert the mock returns what it was told to return (e.g. line 155-159 sets findAppByShortCode -> {id:'app-123'} then asserts it returns {id:'app-123'}). The real branching logic - bypass-then-role precedence in isStaff, guild/guildId rejection + reply in requireInteractionStaff, and the guild-mismatch / null-app early returns in resolveApplication - is never executed. A bug such as inverting `shouldBypass`, dropping the `app.guild_id !== guildId` check (a real authz guard, helpers.ts:117), or failing to send the ephemeral 'Guild only.' reply would pass this suite.

**Location:** `tests/features/review/handlers/helpers.test.ts:61-188`
**Category:** dead-code | **Confidence:** high | **Audit severity:** medium (adversarially confirmed)

**Suggested fix:** Import isStaff/requireInteractionStaff/resolveApplication from helpers.js and assert their real return values and side-effects (reply/replyOrEdit called with the right content/flags, null returned on guild mismatch). Keep shouldBypass/hasRole/findAppByShortCode/loadApplication mocked as inputs.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0208. See audit/2026-05-31/full-codebase-audit.md.
