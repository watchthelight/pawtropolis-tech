# #00212 -- Panic-mode claim error mis-parses ClaimError message, showing "application is already **is**"

**Type:** bug | **Priority:** Low

For an INVALID_STATUS ClaimError the handler builds the user message via `err.message.split(" ")[2]`. This assumes the message is exactly `Application already <status>` (reviewActions.ts:82), where token[2] is the status -> correct for terminal states. But claimTx ALSO throws INVALID_STATUS for panic mode with message "Panic mode is active. All review operations are suspended." (reviewActions.ts:62). split(" ")[2] of that is "is", so a moderator clicking Claim while panic mode is active sees: "Cannot claim: application is already **is**." -- nonsensical and hides the real (panic) reason. It also needlessly calls ensureReviewMessage to "refresh" for a non-status condition.

**Location:** `src/features/review/handlers/claimHandlers.ts:49-50`
**Category:** correctness | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Stop string-slicing err.message. Either add a dedicated error code for panic mode (e.g. PANIC_MODE) or pass the status in a structured field on ClaimError and branch on it. At minimum, special-case the panic message text before the generic INVALID_STATUS branch.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0159. See audit/2026-05-31/full-codebase-audit.md.
