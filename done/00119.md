# #00119 -- Crash recovery loads game-night sessions into the movie session map

**Type:** bug | **Priority:** Medium

recoverPersistedSessions() reads active_movie_events and active_movie_sessions with NO event_type filter, even though those tables are shared with game nights (gameNight.ts persists rows with event_type='game'). gameNight.recoverPersistedGameSessions (gameNight.ts:444,467) correctly filters WHERE event_type='game', but the movie recovery does not. After a restart, game-night active events/sessions are loaded into movieSessions/activeEvents and will be treated as movie attendance (e.g. surfaced by /movie resume, finalized as movie rows). Both recovery paths run at startup, so the game rows get pulled into both maps.

**Location:** `src/features/movieNight.ts:588-623`
**Category:** correctness | **Confidence:** high | **Audit severity:** medium (adversarially confirmed)

**Suggested fix:** Filter the movie recovery queries to event_type='movie' (or IS NULL for legacy rows): add WHERE event_type='movie' to both SELECTs in recoverPersistedSessions, mirroring gameNight.ts.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0148. See audit/2026-05-31/full-codebase-audit.md.
