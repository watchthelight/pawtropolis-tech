# #00089 -- Cron-scheduled prod script imports undeclared @xenova/transformers and fetches remote model weights

**Type:** chore | **Priority:** High

scripts/embed-incremental.mjs (and embed-all.mjs, embed-gold.mjs) do `import { pipeline, env } from '@xenova/transformers'`, but @xenova/transformers is NOT present in either package.json or package-lock.json (grep across both manifests and both lockfiles: 0 occurrences). The cross-file break: deploy.sh:408 ships the entire `scripts/` dir to the prod host, and scripts/quality-cron.txt:14 schedules `node scripts/embed-incremental.mjs` every 30 minutes on EC2 (/home/ubuntu/pawtropolis-tech). But the production install runs `npm ci --omit=dev` (deploy.sh:341/421/428), which can only ever install what is in the lockfile. Since the package is in NO manifest, npm never provisions it. Two possibilities, both bad: (a) the cron job has been failing every 30 min with MODULE_NOT_FOUND, logging silently to /tmp/quality-embed.log which the file itself says nobody rotates/checks; or (b) someone ran an out-of-band `npm install @xenova/transformers` directly on prod, meaning an unpinned, lockfile-untracked package runs every 30 min outside any reproducible/auditable dependency set. A prior in-repo audit (audit/2026-05-19/deps-ops-findings.md, Finding 1) flagged @xenova/transformers as carrying a HIGH-severity vuln via onnxruntime-web and removed it from package.json, but these importing scripts were left behind. Worse, embed-incremental.mjs:18 sets `env.allowLocalModels = false` and line 47 calls `pipeline('feature-extraction', 'Xenova/all-MiniLM-L6-v2')`, which downloads model weights from the HuggingFace CDN at runtime with no integrity/version pinning -- a remote executable-artifact fetch in a scheduled prod job.

**Location:** `scripts/embed-incremental.mjs:14,18,46-47 (also scripts/embed-all.mjs:10, scripts/embed-gold.mjs:11; scheduled by scripts/quality-cron.txt:14)`
**Category:** Dependency / supply-chain | **Confidence:** high | **Audit severity:** high (adversarially confirmed)

**Suggested fix:** Decide intent. If the chat-quality pipeline is live: add @xenova/transformers to package.json dependencies pinned to a specific audited version (or isolate it in a dedicated workspace/package with its own lockfile), commit the lockfile so `npm ci` provisions it deterministically, and pin/vendor the model (set allowLocalModels=true with a checked-in model dir, or pin a model revision) so prod does not pull unverified weights every 30 min. If the pipeline is dead, remove embed-*.mjs and the corresponding quality-cron.txt entry. Either way, stop relying on an out-of-band manual install on prod.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0358. See audit/2026-05-31/full-codebase-audit.md.
