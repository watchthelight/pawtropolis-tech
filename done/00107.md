# #00107 -- Exported CSVs accumulate forever in data/exports despite "expires in 24 hours" claim

**Type:** bug | **Priority:** Medium

Each export writes a uniquely-named file (stats-history-<modId>-<ts>-<rand>.csv, up to MAX_EXPORT_ROWS=50000 rows) into data/exports via writeFileSync, but nothing ever deletes them. I searched the whole repo (schedulers, startup tasks, scripts) for any cleanup of data/exports or any honoring of the advertised 24h expiry - there is none. The embed text "Link expires in 24 hours" is therefore false, and the directory grows unboundedly on every invocation. On the 2GB-RAM / constrained-disk host described in src/db/db.ts, repeated large exports can fill the volume. Combined with finding above, these files are also never even served, so they are pure dead weight.

**Location:** `src/commands/stats/history.ts:236-248, 269-274`
**Category:** leak | **Confidence:** high | **Audit severity:** medium (adversarially confirmed)

**Suggested fix:** Stop persisting to disk and attach the buffer to the reply (preferred). If on-disk staging is required, add a scheduler that prunes data/exports files older than 24h (matching the promise), or write to an OS temp dir and unlink after streaming.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0061. See audit/2026-05-31/full-codebase-audit.md.
