# #00182 -- detectModmailResponseTime wraps indexed TEXT column in strftime(), forcing a full ticket scan

**Type:** bug | **Priority:** Low

The Pulse insights detector filters modmail_ticket with `WHERE mt.guild_id = ? AND strftime('%s', mt.created_at) >= ? AND strftime('%s', mt.created_at) < ?` (line 1179) and also computes `strftime('%s', mm.created_at) - strftime('%s', mt.created_at)` per message. Wrapping the column `mt.created_at` in strftime() makes the time-range predicate non-sargable: SQLite cannot use the available index on modmail_ticket(guild_id, status) (migration 038) to seek on the time bound, and there is no expression index on strftime(created_at). The query runs twice per Pulse load (this-window + prior-window) inside getInsights, and joins every matching ticket to modmail_message. created_at is declared TEXT (confirmed via modmail_message migration 021 / modmail_ticket schema and the strftime usage), so this is a genuine scan, not an index seek. A secondary correctness smell: strftime('%s', ...) returns a string compared against a numeric bind param, relying on SQLite type coercion. Impact is bounded today because (a) the whole Pulse bundle is cached (CACHE_TTL.medium, in-flight dedup) and (b) ticket volume is moderate, so this is a latent scaling cost rather than an active outage.

**Location:** `web/src/lib/server/queries/pulse.ts:1174-1188`
**Category:** Performance / missing-index (non-sargable predicate) | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Store/compare modmail timestamps as unix-seconds, or compare the raw TEXT column directly against an ISO bound computed in JS (e.g. `mt.created_at >= ?` with an ISO string), so the predicate is sargable against an index on modmail_ticket(guild_id, created_at). Alternatively add an expression index on strftime('%s', created_at). Same treatment applies to the mm.created_at delta if you start filtering on it.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0343. See audit/2026-05-31/full-codebase-audit.md.
