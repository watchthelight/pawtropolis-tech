# #00162 -- User-uploaded identity documents (badges/IDs) are posted to a hardcoded channel and retained indefinitely

**Type:** security | **Priority:** Low

The flow invites users to upload verification documents such as badges and IDs (lines 141-145). Every uploaded image URL is then re-posted into a channel identified by a hardcoded snowflake LOG_CHANNEL_ID = "1430015254053654599" (line 26) as embed images (lines 240-253). Although the prompt asks users to redact PII, this is an honor-system flow and many users will upload un-redacted government-issued IDs / first-responder credentials. The consequences: (1) sensitive PII is durably stored in a Discord channel with whatever broad staff access that channel has, beyond the stated "internal records" need and with no retention/deletion; (2) the channel ID is hardcoded rather than configurable, so if the channel is deleted/changed the documents silently fail to log (caught only by a warn) or, worse, a reused ID could route PII to the wrong channel. The attachment.url values are also CDN links that remain accessible.

**Location:** `src/commands/verify.ts:26, 219-257`
**Category:** security | **Confidence:** medium | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Make the log channel configurable per-guild (e.g. via guild_config) instead of a hardcoded ID, restrict it to a least-privilege staff channel, and avoid persisting raw ID images - store only a boolean "documents provided" or a short-lived reference, and document a deletion policy. At minimum, do not echo the uploaded image URLs into a long-lived channel.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0067. See audit/2026-05-31/full-codebase-audit.md.
