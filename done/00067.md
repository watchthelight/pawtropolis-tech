# #00067 -- Game-night and movie-night attendance overwrite each other (UNIQUE constraint missing event_type)

**Type:** bug | **Priority:** High

finalizeGameAttendance writes to movie_attendance with `INSERT OR REPLACE ... VALUES (..., 'game', ...)` keyed implicitly on the table's UNIQUE constraint. That constraint is `UNIQUE(guild_id, user_id, event_date)` (migrations/025_role_automation.ts:111) and migration 040 (which added the event_type column) only ALTERs in the column + a NON-unique index `idx_movie_attendance_event_type`; it never rebuilds the unique key to include event_type. event_date is a date-only string `YYYY-MM-DD` (src/commands/event/game.ts:92, src/commands/event/movie.ts:88). Movie night finalize uses the same table with the same date (src/features/movieNight.ts:292-295). Therefore, if a user attends both a movie night and a game night on the same calendar day, whichever event is finalized second silently REPLACES the other event's row, destroying the first event's attendance/qualification record and corrupting tier counts (getUserQualifiedGameCount / getUserTotalEventCount). The same applies to creditHistoricalGameAttendance (lines 744-757) and bumpGameAttendance (lines 816-829) whose `ON CONFLICT(guild_id, user_id, event_date)` cannot even reference event_type because it is not a unique key - at runtime this ON CONFLICT clause resolves against the (guild_id,user_id,event_date) unique index and will collide with a movie record of the same day.

**Location:** `src/features/events/gameNight.ts:247-287`
**Category:** data-integrity | **Confidence:** high | **Audit severity:** high (adversarially confirmed)

**Suggested fix:** Add event_type to the uniqueness key: create a migration that rebuilds movie_attendance with `UNIQUE(guild_id, user_id, event_date, event_type)` (SQLite requires create-new-table + copy + drop + rename), or add a separate `CREATE UNIQUE INDEX ... ON movie_attendance(guild_id,user_id,event_date,event_type)` after dropping the old unique index, then update all INSERT OR REPLACE / ON CONFLICT targets accordingly.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0071. See audit/2026-05-31/full-codebase-audit.md.
