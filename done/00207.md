# #00207 -- getClaim returns an object typed as ReviewClaimRow but missing the app_id field

**Type:** bug | **Priority:** Low

This getClaim SELECTs only `reviewer_id, claimed_at` yet casts the result to ReviewClaimRow, whose type declares a non-optional `app_id: string` (types.ts:63-67). At runtime app_id is undefined while the type says it is present - an unsound cast. The sibling implementation in reviewActions.ts:209 correctly selects app_id, reviewer_id, claimed_at, so the two getClaim functions diverge. Current consumers (claimGuard, card.ts) only read reviewer_id/claimed_at, so no crash today, but any future code that trusts the type and reads claim.app_id from this path will get undefined silently.

**Location:** `src/features/review/claims.ts:61-66`
**Category:** types | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Add app_id to the SELECT here (SELECT app_id, reviewer_id, claimed_at ...) to match the declared type and the reviewActions.ts implementation, or narrow the return type to Pick<ReviewClaimRow,'reviewer_id'|'claimed_at'>.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0128. See audit/2026-05-31/full-codebase-audit.md.
