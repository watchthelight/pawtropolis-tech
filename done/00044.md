# #00044 -- Fix wrong table/column names in api/export

**Type:** bug | **Priority:** High

`GET /api/export?type=audit` and `?type=config_audit` both throw at the `prepare` step because the SQL references identifiers that do not exist in the schema:

1. `audit` branch (line 56): selects from `audit_results`. The real table is `audit_findings` (migration 043). The `audit_results` name never existed in any migration.
2. `config_audit` branch (line 76): filters on `changed_at_s INTEGER`. The real `config_audit_log` (migration 060) only has `created_at TEXT DEFAULT (datetime('now'))`. No `changed_at_s` column anywhere.

Production effect: any admin clicking "Audit export" or "Config audit export" gets a 500. The dashboard otherwise looks fine, so this has lived undetected.

Action:
1. Replace `audit_results` -> `audit_findings` in `web/src/routes/api/export/+server.ts:56`. Verify the SELECT columns match the `audit_findings` schema (see migration 043); adjust if needed.
2. Fix the config_audit SELECT to use `created_at` (TEXT) for filtering. Two options: convert the unix-second range to ISO strings before binding (similar to how the audit branch builds dates), or add a `created_at_s INTEGER` column via a new migration and dual-write. The first option is cheaper.
3. Update the two pin tests in `tests/web/routes/export.test.ts` ("audit branch currently throws", "config_audit branch currently throws") to assert the fixed happy paths and the proper tier gates.
4. Add a real-data smoke test against `tests/fixtures/schema.sql` (after adding `audit_findings` rows + applying the `config_audit_log` DDL) so the wire format stays pinned.

**Evidence:** flagged during slice 4 of #00012 (commit message tagging #00044); tests `tests/web/routes/export.test.ts` pin the throws.
