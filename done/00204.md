# #00204 -- Dead defensive check: closeModmailForApplication tests status!=='open' on a query that already filters status=

**Type:** refactor | **Priority:** Low

getOpenTicketByUser only returns rows WHERE status='open' (tickets.ts:59-77), so `if (!ticket || ticket.status !== 'open')` at lines 457-460 can only ever be true via the `!ticket` branch; the status comparison is unreachable. Harmless, but it implies a guard that does not actually exist (it will not catch a 'closed' ticket because such a ticket is never returned here).

**Location:** `src/features/modmail/threadClose.ts:456-460`
**Category:** dead-code | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Drop the redundant status comparison, or fetch via a status-agnostic lookup (getTicketById/getTicketByThread) if the intent is genuinely to re-check status.
