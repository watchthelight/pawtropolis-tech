# #00115 -- create() creates the Discord channel before the DB insert; an insert failure orphans an untracked channel

**Type:** bug | **Priority:** Medium

The Discord channel is created at line 241 (guild.channels.create), and only after that does getInsertTicketStmt().run(...) insert the tracking row (line 252). create() is not wrapped in any compensating try/catch. If the DB insert throws (e.g., ticket table missing per the lazy-prepare warning at lines 39-44, a constraint violation, or a transient SQLite error), the function rejects but the Discord channel already exists with no corresponding ticket row. It will never be found by findByChannelId, never closed by the lifecycle, and the allocated number is consumed. The handler (handlers.ts:247) just reports the error to the user, leaving a permanent orphan channel under the Tickets category.

**Location:** `src/features/tickets/service.ts:241-261`
**Category:** data-integrity | **Confidence:** medium | **Audit severity:** medium (adversarially confirmed)

**Suggested fix:** Insert the DB row first (using a placeholder channel_id is awkward), or wrap the post-create steps in try/catch and delete the freshly-created channel (channel.delete()) if the DB insert fails, so a failed open leaves no orphan.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0116. See audit/2026-05-31/full-codebase-audit.md.
