# #00129 -- buttons.test.ts never imports the button handlers; all assertions are local re-implementations

**Type:** refactor | **Priority:** Medium

Despite describe blocks for handleReviewButton/handleModmailButton/handlePermRejectButton/handleCopyUidButton/handlePingInUnverified/handleDeletePing, the file never imports buttons.ts and never calls any handler. The customId regexes are re-declared inline (e.g. line 84 BUTTON_RE, line 155 BTN_MODMAIL_RE) instead of imported from src/lib/modalPatterns.js, so if the real regex drifts from the test copy the tests still pass. Routing assertions are tautologies, e.g. line 100-103 `const opensModal = ["reject",...].includes("reject"); expect(opensModal).toBe(true)`. Security-relevant behavior in the real handler is therefore untested: requireInteractionStaff gating (buttons.ts:77,216,286,319,637), the per-action rate-limit deferUpdate path (buttons.ts:84-92), allowedMentions hardening on the unverified ping (buttons.ts:494 `{users:[userId],parse:[]}`), and findAppByShortCode existence check before replying with a UID (buttons.ts:334). A regression that, say, dropped the staff check or widened allowedMentions would not fail here even though 'permission checks' tests exist. Impact: false confidence on a moderator-only, mention-capable surface.

**Location:** `tests/features/review/handlers/buttons.test.ts:72-479`
**Category:** dead-code | **Confidence:** high | **Audit severity:** medium (adversarially confirmed)

**Suggested fix:** Import BUTTON_RE/BTN_* from src/lib/modalPatterns.js so the test exercises the real patterns, and invoke the exported handlers with mocked ButtonInteraction objects, asserting that non-staff interactions get the 'Gatekeeper role required' reply and that the ping path sends with parse:[] and only the target user. Remove the tautological `.includes(...)` literal assertions.
