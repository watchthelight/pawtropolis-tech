# #00139 -- Unrecognized modal customId prefixes are silently dropped with no ack and no error card

**Type:** bug | **Priority:** Medium

The isModalSubmit() block handles a fixed set of prefixes (tk:closemod:, help:modal:search, v1:modal:/v1:avatar:confirm18:, v1:gate:reset:, isitreal_modal_). A route-miss error card is posted ONLY inside the v1:modal:/v1:avatar: branch (lines 981-1000). A modal whose customId matches none of these prefixes falls through to the end of the function and returns without ever acknowledging the interaction - no reply, no deferUpdate, no error card, not even a route-miss log. The user sees Discord's generic 'Something went wrong' and there is no trace ID. This is exactly the failure mode that occurs after renaming a modal customId or shipping a new modal without registering its route - the symptom is invisible in logs. Contrast with the slash path (line 234-251) and the inner modal route-miss, both of which respond/log.

**Location:** `src/events/interactionCreate.ts:726-1025`
**Category:** correctness | **Confidence:** high | **Audit severity:** medium (adversarially confirmed)

**Suggested fix:** Add a final else at the end of the isModalSubmit() block that logs evt:'ix_route_miss' and posts the same postErrorCard route-miss as the inner v1:modal: branch, so any unhandled modal yields an acknowledgement and a reportable trace ID.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0270. See audit/2026-05-31/full-codebase-audit.md.
