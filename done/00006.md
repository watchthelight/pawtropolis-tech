# #00006 -- Add Origin header CSRF check on dashboard API state-changing routes

**Type:** security | **Priority:** Medium | **Status:** `COMPLETE 2026-05-19`

src/web/dashboardApi.ts authenticates via X-Dashboard-Secret header but does not validate the Origin header. State-changing routes (review/approve, review/reject, modmail/send, qotd/approve, etc.) are accessible from any origin if the browser carries the cookie. SvelteKit form CSRF tokens are not used either.

**Resolution (2026-05-19):** Added second `onRequest` hook in src/web/dashboardApi.ts (commit 34d8f27). Allowlist sourced from `DASHBOARD_ALLOWED_ORIGINS` env var (comma-separated), defaulting to `https://pawtropolis.tech`. Logic:
- GET/HEAD/OPTIONS bypass the check (read-only).
- Absent Origin header passes (server-to-server callers; secret already authenticated).
- Origin present but not on allowlist returns 403 + logger.warn.

Added `DASHBOARD_ALLOWED_ORIGINS` to .env.example with usage notes. Unit tests deferred to a future tick.

Action:
1. Add a Fastify hook that checks `request.headers.origin` matches a configured dashboard origin allowlist for any POST/PUT/PATCH/DELETE route.
2. Return 403 with a JSON error on mismatch.
3. Add the dashboard origin (or a list of allowed origins) to the env config.
4. Add unit tests covering allowed origin, blocked origin, missing origin.
