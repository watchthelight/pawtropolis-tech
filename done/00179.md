# #00179 -- Command-center decisionsToday and weekStats omit 'perm_reject', undercounting decisions and skewing avg respon

**Type:** bug | **Priority:** Low

decisionsToday (line 74) and the weekStats decisions+avg query (line 88) filter `action IN ('approve', 'reject', 'kick')`, omitting 'perm_reject'. Permanent rejections ARE written to review_action with action='perm_reject' (src/features/review/flows/reject.ts:69-77: `const action = permanent ? 'perm_reject' : 'reject'`). Every other decision query in the codebase consistently uses the 4-verb set `('approve','reject','perm_reject','kick')` (see web/src/lib/server/queries/stats.ts and observatory refresh). A grep confirms home.ts lines 74 and 88 are the ONLY occurrences of the 3-verb set anywhere. Result: the home dashboard's 'decisions today' and 'this week' counts under-report by the number of permanent rejections, and the weekly avg-response-time computation excludes perm_reject decisions entirely, so its mean is biased.

**Location:** `web/src/lib/server/queries/home.ts:73-74, 81-91`
**Category:** double counting / undercount (action set drift) | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Add 'perm_reject' to both IN lists so home.ts matches the rest of the system: `action IN ('approve', 'reject', 'perm_reject', 'kick')`.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0311. See audit/2026-05-31/full-codebase-audit.md.
