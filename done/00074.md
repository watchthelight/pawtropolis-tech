# #00074 -- Unclaim feedback/errors also leak onto the public review card (same deferUpdate + stripped-flags path)

**Type:** bug | **Priority:** High

handleUnclaimAction is invoked from handleUnclaimModal (src/features/review/handlers/modals.ts:242-270), which calls interaction.deferUpdate() before delegating. As with claim, interaction.deferred is true, so every replyOrEdit({ ..., flags: MessageFlags.Ephemeral }) here (NOT_CLAIMED / NOT_OWNER / APP_NOT_FOUND error strings, the unexpected-error string, and the 'Application `CODE` unclaimed successfully.' confirmation at 243-248) is turned into a public editReply on the review card with the ephemeral flag discarded (src/lib/cmdWrap.ts:505). Owner-mismatch and not-claimed messages intended for one mod are shown to the whole channel and clobber the card's content line.

**Location:** `src/features/review/handlers/claimHandlers.ts:178-184, 190-195, 243-248`
**Category:** correctness | **Confidence:** high | **Audit severity:** high (adversarially confirmed)

**Suggested fix:** Same as the claim finding: send these as interaction.followUp({ content, flags: MessageFlags.Ephemeral }) instead of relying on replyOrEdit (which drops flags on the deferred/editReply branch).

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0119. See audit/2026-05-31/full-codebase-audit.md.
