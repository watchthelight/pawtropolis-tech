# #00086 -- ensurePokeConfigColumns() is never called -> poke config columns missing in prod DB -> /config poke crashes

**Type:** refactor | **Priority:** High

ensurePokeConfigColumns (config.ts:492) is the ONLY code path that adds guild_config.poke_category_ids_json and poke_excluded_channel_ids_json. There is no migration for them (grep 'poke' across migrations/ = zero hits) and they are absent from tests/fixtures/schema.sql. The startup self-heal runner src/startup/schema.ts wires in 7 other config ensure* functions (lines 67-73) but omits ensurePokeConfigColumns, despite its own comment (schema.ts:11-12) saying new ensure* functions must be appended. git log -S 'ensurePokeConfigColumns' confirms the function was never referenced from index.ts/schema.ts. I opened the live production DB (DB_PATH=./data/data.db, 5GB, actively used) and confirmed both columns are ABSENT. Meanwhile /config poke (config/poke.ts) calls upsertConfig({ poke_category_ids_json: ... }); poke_category_ids_json is in the upsertConfig ALLOWLIST (config.ts:659) so it is NOT filtered out, and upsertConfig builds 'UPDATE guild_config SET poke_category_ids_json = ?' (config.ts:682). Against a table lacking the column this throws SqliteError: no such column: poke_category_ids_json. So setting poke target categories / excluded channels is currently a hard runtime failure in production, caused purely by an ensure function that is dead because nobody wired it in.

**Location:** `src/lib/config.ts:492-532 (defn); src/startup/schema.ts:41-73 (omission); src/commands/config/poke.ts:69,140,210,281 (callers)`
**Category:** Dead/unwired code causing runtime failure | **Confidence:** high | **Audit severity:** high (adversarially confirmed)

**Suggested fix:** Add ensurePokeConfigColumns and ensurePulseConfigColumns to the import block and call list in src/startup/schema.ts:runSchemaSelfHeal() (alongside ensureSkullModeColumns etc.). Alternatively delete the dead ensure functions and add a real numbered migration under migrations/ that ALTER TABLE ADD COLUMN the poke/pulse columns, then run npm run migrate on prod. Either way the column-add must actually execute before /config poke is used.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0328. See audit/2026-05-31/full-codebase-audit.md.
