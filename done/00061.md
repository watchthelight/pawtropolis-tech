# #00061 -- /backfill spawns a non-existent script - command is permanently broken

**Type:** bug | **Priority:** Critical

execute() spawns `npx tsx scripts/backfill-message-activity.ts <guildId> <weeks> [--dry-run]`, but that file does not exist anywhere in the repo (verified via filesystem + grep; the only references to `backfill-message-activity` are this command, the legacy BACKFILL-NOW.sh, and docs). The real backfill entrypoint is `scripts/backfill/run.ts`, which has a completely different CLI (`--channels=...`, `--skip-reactions`, `--resume-only`) and takes no positional guildId/weeks args. As a result every /backfill invocation immediately fails: tsx exits non-zero with a module-not-found error, the `close` handler reports `❌ Backfill Failed` (or the `error` handler logs a spawn failure), and no data is ever backfilled. The heatmap that /backfill is meant to populate stays empty. Staff-facing command that can never succeed.

**Location:** `src/commands/backfill.ts:137-140`
**Category:** correctness | **Confidence:** high | **Audit severity:** critical (adversarially confirmed)

**Suggested fix:** Point spawn at the actual script and pass the arguments it expects, e.g. `spawn('npx', ['tsx', 'scripts/backfill/run.ts', ...])` adapted to run.ts's flag-based interface (it currently parses `--channels=` etc., not positional guildId/weeks). Either add a thin `scripts/backfill-message-activity.ts` shim that accepts `<guildId> <weeks>` and calls into the run.ts logic, or rewrite the command to invoke run.ts with the flags it supports. Also update BACKFILL-NOW.sh. Add a smoke test that asserts the spawned script path exists.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0033. See audit/2026-05-31/full-codebase-audit.md.
