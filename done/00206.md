# #00206 -- close() writes the permanent archive BEFORE applying the closed state, so the archive records the ticket as st

**Type:** bug | **Priority:** Low

In close(), writeArchive(ticket) is awaited at line 465 using the in-memory ticket object fetched by findById (status='open', closedAt=null, closeReason=null). Only afterward (line 466) does getSetClosedStmt() flip status to 'closed' and set closed_at/close_reason. writeArchive serializes that stale ticket object into the JSON payload (service.ts:560-568 `payload.ticket = ticket`). The archive file - the long-term auditable record the module exists to produce - therefore says status:'open', closedAt:null, closeReason:null for a ticket that is being closed. The 'closed' and 'archived' events are captured, but the embedded ticket snapshot is wrong.

**Location:** `src/features/tickets/service.ts:458-467, 544-569`
**Category:** data-integrity | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Run getSetClosedStmt() first, then re-read the row (or mutate the local object's status/closedAt/closeReason/closedByUserId) and pass the closed snapshot to writeArchive, so the archived ticket reflects its terminal state.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0115. See audit/2026-05-31/full-codebase-audit.md.
