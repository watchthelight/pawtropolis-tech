# #00222 -- Tautological tests re-implement logic inline instead of calling the source (false confidence)

**Type:** refactor | **Priority:** Low

Large blocks of this suite never invoke any function from src/features/modmail/threadClose.ts. The 'reason text' tests (lines 255-307) copy-paste the exact reason-selection ternary from threadClose.ts (source lines 466-473) into the test body and assert on the copy. Likewise the 'closing embed format' (lines 311-330), 'archive/delete strategies' (lines 332-351, re-implementing `cfg?.modmail_delete_on_close !== false`), 'log URL format' (lines 353-361), 'duplicate close detection' (lines 364-377), and 'ticket structure' (lines 380-408) blocks only assert against literals/inline expressions defined within the test. These tests pass unconditionally regardless of the real implementation, so if someone changes the reason wording, the embed color/title, the delete-on-close default, or the log-URL template in threadClose.ts, these tests will NOT fail. Impact: false sense of coverage for closeModmailForApplication's user-facing strings and close behavior; a real regression in those strings would ship undetected.
