# #00099 -- Legacy scripts/deploy.sh ships migrations/ but never runs them, restarting new code on an old schema

**Type:** bug | **Priority:** Medium

scripts/deploy.sh builds a tarball that includes `migrations` and `scripts` (line 108) and on the remote runs only: extract -> `npm ci --omit=dev` -> `pm2 restart` (lines 123-133). There is no `node scripts/migrate-remote.js` / `migrate.ts` step anywhere (grep confirms 0 occurrences of 'migrate'). So anyone running this script (or following the older docs that reference `./deploy.sh`) deploys new code that expects new schema, but the schema is never advanced. The new bot then hits missing columns/tables. This is the inverse-yet-equivalent failure of the root deploy.sh issue and is easy to trigger because two same-named scripts exist (root `deploy.sh` with migrations, `scripts/deploy.sh` without). It also has no deploy lock and no pre-deploy DB backup, unlike the hardened root script.

**Location:** `C:/Users/Claude-Code/pawtropolis-tech/scripts/deploy.sh:105-133`
**Category:** deploy-safety/schema-drift | **Confidence:** high | **Audit severity:** medium (adversarially confirmed)

**Suggested fix:** Either delete scripts/deploy.sh entirely (the hardened root deploy.sh supersedes it) or add the migration step before `pm2 restart` and a pre-deploy backup + lock. At minimum, have it `exec` the root deploy.sh so there is a single source of truth and no path that skips migrations.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0352. See audit/2026-05-31/full-codebase-audit.md.
