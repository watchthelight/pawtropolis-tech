# #00246 -- Remote migration wrapper exits 0 when the migration child is killed by a signal

**Type:** bug | **Priority:** Low

spawnSync runs scripts/migrate.ts and then `process.exit(result.status || 0)`. When the child process is terminated by a signal rather than a normal exit (OOM kill, SIGTERM during deploy), spawnSync sets `result.status` to null and `result.signal` to the signal name. `null || 0` evaluates to 0, so this wrapper reports SUCCESS even though the migration was killed mid-run. A deploy script keying off this exit code would proceed as if migrations completed. (A normal migration failure is fine: migrate.ts exits 1, status=1, 1||0=1.)

**Location:** `scripts/migrate-remote.js:18-24`
**Category:** error-handling / exit-code masking | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Treat signal death and null status as failure: `if (result.status === null) process.exit(1); process.exit(result.status);` (or `process.exit(result.status ?? 1)` and also check result.signal/result.error).

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0308. See audit/2026-05-31/full-codebase-audit.md.
