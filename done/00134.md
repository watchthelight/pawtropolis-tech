# #00134 -- "clamps odds to minimum/maximum" tests are vacuous: odds=0 is coerced to 1000 before the clamp, and mocked con

**Type:** bug | **Priority:** Medium

Two problems. (1) The test 'clamps odds to minimum' (line 265-272) sets dadmode_odds: 0 and expects a reply. But the source (src/listeners/messageDadMode.ts:73) computes `odds = Math.max(DADMODE_ODDS_MIN, Math.min(DADMODE_ODDS_MAX, Number(cfg.dadmode_odds || 1000)))`. Because `0 || 1000` evaluates to 1000 (0 is falsy), the value 0 is replaced by 1000 BEFORE reaching Math.max, so the DADMODE_ODDS_MIN clamp branch is never exercised - the test name is misleading and the lower-bound clamp is effectively untested. (2) The test mocks src/lib/constants.js (line 27-30) with DADMODE_ODDS_MIN:1, DADMODE_ODDS_MAX:10000, but the real constants (src/lib/constants.ts:34-35) are DADMODE_ODDS_MIN:2, DADMODE_ODDS_MAX:100000. So 'clamps odds to maximum' (line 274-282) asserts a 10000 ceiling that does not exist in production (real ceiling 100000). A regression that changed the real MIN/MAX constants would not be caught by these tests. Impact: false confidence that odds clamping is validated; the actual production clamp bounds are untested.

**Location:** `tests/listeners/messageDadMode.test.ts:265-282`
**Category:** correctness | **Confidence:** high | **Audit severity:** medium (adversarially confirmed)

**Suggested fix:** Use a non-falsy out-of-range value to exercise the lower clamp (e.g. dadmode_odds: -5 or 1, which survives the `|| 1000` guard and reaches Math.max(DADMODE_ODDS_MIN,...)). Do NOT mock constants.js (or mock it with the real values) so the test validates the production bounds; assert the effective odds via the number of Math.random buckets or by spying on the computed odds.
