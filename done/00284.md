# #00284 -- v26 measured optimizations

**Type:** refactor | **Priority:** Medium

From the v26 audit (`MODERNIZATION_PLAN.md` section 3): PERF-1 fractional day buckets (wrong weekly active users and Pulse chart, oversized result sets), PERF-3 missing `message_activity(guild_id, user_id)` index, PERF-4 `/activity` heatmap reads raw rows, PERF-5 member handlers wait on a log send, PERF-9 synchronous PNG encode.

Each change carries a before and after number. No number, no claim.

**Resolution (2026-11-14, 26.0.0):** four changes shipped, measured on a read-only copy of the production database unless noted.

- PERF-1: stats refresh query 1084 ms to 747 ms (478,091 rows to 9,899); Pulse daily query for 30 days 119 ms to 32.5 ms. Weekly active users and the Pulse daily chart now show different numbers, because the old ones were wrong.
- PERF-3: a 100-member `/audit members` pass went from 13,694 ms to 310 ms by loading the guild's authors once. The index was measured and rejected: 4.8 s to build, 95 MB, and it slowed a 50,000-row insert from 470 ms to 1,558 ms.
- PERF-4: `/activity` heatmap for 8 weeks 69.7 ms to 32.1 ms.
- PERF-9: PNG encode no longer blocks the event loop: 100.0 ms to 0.4 ms on a 1600x1900 canvas (stall probe, not a database number).

PERF-5 was not shipped. Its cost is a Discord round trip that cannot be measured locally, so it moved to #00286.
