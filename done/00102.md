# #00102 -- Backfill cooldown is consumed before validation and before the (failing) spawn, locking the guild out for 30 m

**Type:** bug | **Priority:** Medium

checkCooldown('backfill', guildId, COOLDOWNS.BACKFILL_MS) records the cooldown timestamp as a side effect on the *allowed* path (see rateLimiter.ts:77 - it sets `now` whenever it returns allowed:true, even if the caller never proceeds). It is called before the weeks/date validation and before the child process is spawned. Combined with the broken-script bug above, a single attempt fails instantly yet still burns the full 30-minute BACKFILL_MS cooldown for the entire guild, so staff cannot retry for half an hour after every failed run. Even independent of the missing-script bug, if spawn errors or validation rejects the input, the cooldown has already been consumed.

**Location:** `src/commands/backfill.ts:85-92`
**Category:** correctness | **Confidence:** high | **Audit severity:** medium (adversarially confirmed)

**Suggested fix:** Move checkCooldown after input validation, and ideally only record the cooldown once the child process has actually been spawned successfully (e.g. inside backfillProcess.on('spawn'), or call clearCooldown('backfill', guildId) in the 'error' handler and on validation failure).

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0034. See audit/2026-05-31/full-codebase-audit.md.
