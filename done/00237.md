# #00237 -- Flat (no-change) delta emits the green UP-vote emoji in the copied newsletter

**Type:** bug | **Priority:** Low

In numDelta (line 36-37) and pctDelta (line 50-51) the `direction` is computed as `abs > 0 ? 'up' : abs < 0 ? 'down' : 'flat'`, but the `emoji` is computed as `abs >= 0 ? UP_EMOJI : DOWN_EMOJI`. When the current and previous values are equal and non-zero (the `prev===0 && cur===0` early-returns do not fire), `abs === 0`, so `direction` is correctly 'flat' but `emoji` is UP_EMOJI. The Discord markdown builder (discordMarkdown, lines 76 and 92-102) unconditionally prints `d.X.emoji` next to the percentage, so a metric that did not change week-over-week renders a green up-vote (<:Iup_Vote:...>) beside a '+0.0%' line. The text copied for the public newsletter therefore signals growth where there was none.

**Location:** `web/src/lib/components/pulse/NewsletterStatsCard.svelte:28-53, 71-104`
**Category:** correctness | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Derive the emoji from `direction` instead of the `>= 0` sign, e.g. `emoji: direction === 'down' ? DOWN_EMOJI : direction === 'up' ? UP_EMOJI : NEUTRAL_EMOJI` (or reuse UP only for true 'up'). At minimum compute emoji from the already-correct `direction` value so flat never maps to the up emoji.
