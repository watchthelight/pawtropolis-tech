# #00140 -- Third legacy deploy script skips migrations entirely and uses set -e without pipefail/-u

**Type:** bug | **Priority:** Medium

scripts/deploy.sh (distinct from the root deploy.sh) is yet another deploy path to the same prod host. It uses only `set -e` (line 12) - no `-u` (undefined vars silently empty) and no `pipefail` (a failing command upstream of a pipe is masked). More importantly it has NO migration step at all: it extracts the tarball, runs `npm ci --omit=dev`, and `pm2 restart` (lines 122-133), so deploying through this script ships new code that expects a new schema without ever running migrations. Its tarball (line 108) also omits .env.build, web/build, and ecosystem.config.cjs that the root deploy.sh ships, so the build-info/runtime env and web app drift. Having three divergent deploy scripts (root deploy.sh, deploy-no-tests.sh, scripts/deploy.sh) all pointed at PM2 process 'pawtropolis' is a maintenance trap where the safe behavior depends entirely on which file the operator happens to run.

**Location:** `scripts/deploy.sh:12,108,122-133`
**Category:** deploy-safety | **Confidence:** high | **Audit severity:** medium (adversarially confirmed)

**Suggested fix:** Remove or clearly archive scripts/deploy.sh; converge on the root deploy.sh. If kept, add `set -euo pipefail` and the migration step, and make the tarball contents identical to the canonical deploy.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0293. See audit/2026-05-31/full-codebase-audit.md.
