# #00199 -- listCandidates maps foreign_key_violations from the row_count column

**Type:** bug | **Priority:** Low

When building a BackupCandidate from persisted metadata, `foreign_key_violations: existingMeta?.row_count` reads the wrong column (row_count) - a copy-paste error. The db_backups table (migrations/012:52-62) has no foreign-key-violation column at all, and validateCandidate persists only row_count (the summed row total). Consequently any UI/embed that shows cached FK violations for a not-yet-revalidated candidate will display the total row count as the FK-violation count, which is misleading (e.g., a healthy backup appears to have thousands of FK violations).

**Location:** `src/features/dbRecovery.ts:205-207`
**Category:** correctness | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Set `foreign_key_violations: undefined` here (it is not persisted), or add a dedicated `foreign_key_violations` column to db_backups and persist/read it. Do not alias it to row_count.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0073. See audit/2026-05-31/full-codebase-audit.md.
