# #00293 -- Move the host to Node 24

**Type:** chore | **Priority:** High

Owner decision 5 (#00287): the whole host moves from Node 20 to Node 24 through apt, together with the 26.1.0 deploy.

Seen on the host on 2026-11-15: Node 20.20.2 comes from the NodeSource apt package and every PM2 app on the host runs on it, not only the bot and the dashboard. Node 20 passed its end of life in April 2026; Node 24 is supported to April 2028.

Before the switch, without touching a running app:

- List every app on the host with its native modules and its `engines` range.
- Install each app's dependencies under Node 24 in a temp copy and load its native modules.

At the switch: change the apt source to Node 24, reinstall each app's dependencies, restart, check each app. The way back is the Node 20 apt package and the same reinstall.

Done on 2026-11-15, in the maintenance window of the 26.1.0 deploy: the host runs Node 24.22.3. The release went out on Node 20 first. Then apt replaced the package with `needrestart` suspended, so that the install restarted no service. The other Node apps were restarted one at a time, their compiled modules rebuilt first. A second deploy installed the bot's and the dashboard's dependencies again, and the PM2 daemon was restarted last. Every app was checked after its restart and all of them once more at the end. The timeline, the checks and the way back are in `docs/releases/26.1.0.md`.

Two fixes came out of the preparation: the deploy installs again when the host's Node major changes (`3d882eff`), and it saves the PM2 process list after a restart (`b4b4bfd5`).

Left for #00286, once the way back to Node 20 is given up: the Node 20 test leg leaves CI, the `engines` floor and the build target go up, and better-sqlite3 no longer has to stay at or under 12.9.1 for its Node 20 binary.
