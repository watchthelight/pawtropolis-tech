# #00195 -- searchCommands scoring compares the full multi-word query against single command names, so every multi-term se

**Type:** bug | **Priority:** Low

After AND-matching individual terms, the scoring block sets `queryLower = query.toLowerCase()` (the entire raw query, line 156) and compares it with `lowerName === queryLower`, `lowerName.startsWith(queryLower)`, `lowerName.includes(queryLower)`, alias includes, etc. For any multi-word query (e.g., 'role config'), no single command name/alias contains the full multi-word string, so all branches fail and every result is scored 50 / matchedOn='description' (lines 181-184). The subsequent sort (line 190-193) then degenerates to pure alphabetical order, defeating relevance ranking for multi-term searches. Single-word searches are unaffected. Impact is degraded result ordering only, not wrong results, so low severity.

**Location:** `src/commands/help/cache.ts:155-184`
**Category:** correctness | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Score against individual terms rather than the whole query - e.g., compute the best per-term match (max over terms of name-exact/startsWith/includes) instead of using the full `query` string, or score using the first term and use the rest only for filtering.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0051. See audit/2026-05-31/full-codebase-audit.md.
