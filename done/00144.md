# #00144 -- getApplicationFunnel counts status='perm_rejected', a status the bot never writes, so permRejected is always 0

**Type:** refactor | **Priority:** Medium

The funnel query has `SUM(CASE WHEN status = 'perm_rejected' THEN 1 ELSE 0 END) as perm_rejected` and also lists 'perm_rejected' in the 'submitted' rollup. But there is no 'perm_rejected' application status anywhere: the application CHECK constraint only allows ('draft','submitted','approved','rejected','needs_info','kicked') (tests/fixtures/schema.sql:201) and the reject transaction sets status='rejected' (with permanently_rejected=1) for BOTH normal and permanent rejections (src/features/review/flows/reject.ts:82-91). This is documented in src/features/gate/drafts.ts:193 and src/commands/listopen.ts:46: 'Permanently rejected apps have status=\'rejected\' with permanently_rejected=1'. Consequences: FunnelMetrics.permRejected is permanently 0, and every permanent rejection is counted in the `rejected` bucket -- the funnel cannot distinguish them. The query ignores the application.permanently_rejected flag entirely.

**Location:** `web/src/lib/server/queries/stats.ts:699-724`
**Category:** schema drift / dead predicate | **Confidence:** high | **Audit severity:** medium (adversarially confirmed)

**Suggested fix:** Count permanent rejections via the real signal: `SUM(CASE WHEN status='rejected' AND permanently_rejected=1 THEN 1 ELSE 0 END) AS perm_rejected` and, if `rejected` should exclude them, `SUM(CASE WHEN status='rejected' AND COALESCE(permanently_rejected,0)=0 THEN 1 ELSE 0 END) AS rejected`. Drop 'perm_rejected' from the status IN-lists.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0312. See audit/2026-05-31/full-codebase-audit.md.
