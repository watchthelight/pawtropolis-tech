# #00066 -- Patreon art-grant backfill iterates role.members without fetching members → silently grants nothing

**Type:** bug | **Priority:** High

After login the script does `const guild = client.guilds.cache.get(guildId)` and then iterates `role.members` (line 100) to backfill `patreon_art_granted` ticket quantities. It never calls `guild.members.fetch()`. `role.members` is a live filter over the guild member cache, which is essentially empty for a freshly-connected client (Discord only pushes a small set during READY even with the GuildMembers intent). As a result `role.members.size` is 0 (or near-0) for every tier, the inner loop never runs, and the script prints 'Processing <tier> (0 members)' followed by 'Backfill complete: 0 members, 0 grant records.' - exiting 0 as if it succeeded. Because this is the one-time economy backfill that must run after migration 062 and before enabling `patreon_art_rewards_enabled`, entitled Patreon supporters silently never get their headshot/fullbody/emoji ticket grants backfilled, and the silent success makes the gap easy to miss. The sibling scripts backfill-user-cache.ts and backfill-user-cache.mjs prove the intended pattern: they `await guild.members.fetch()` before reading members.

**Location:** `scripts/backfill-patreon-art-grants.ts:70-117`
**Category:** correctness | **Confidence:** high | **Audit severity:** high (adversarially confirmed)

**Suggested fix:** Fetch members before reading role membership: replace `const guild = client.guilds.cache.get(guildId)` with `const guild = await client.guilds.fetch(guildId); await guild.members.fetch();` (or call `guild.members.fetch()` immediately after the cache.get null-check). This populates the cache so `role.members` is correctly populated for every tier.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0010. See audit/2026-05-31/full-codebase-audit.md.
