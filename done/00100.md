# #00100 -- Multi-batch message fetch produces non-chronological output (batches interleaved/mis-ordered)

**Type:** bug | **Priority:** Medium

fetchMessagesFromChannel (lines 150-183) fetches messages 100 at a time (newest-first), sorts each batch oldest-first, then prepends each message with messages.unshift(...) (line 167), and finally calls messages.reverse() (line 182). Tracing two batches: batch1 IDs [10,9,8] -> sorted [8,9,10] -> after unshifts messages=[10,9,8]; batch2 (older) IDs [7,6,5] -> sorted [5,6,7] -> after unshifts messages=[7,6,5,10,9,8]; final reverse() yields [8,9,10,5,6,7]. Correct chronological order is [5,6,7,8,9,10]. So any channel/thread with more than 100 messages is archived with the message blocks out of order across every 100-message boundary. The header 'Total messages' count is still correct, so the corruption is silent. For channels under 100 messages (single batch) the output happens to be correct, which masks the bug in light testing.

**Location:** `scripts/fetch-channel.ts`
**Category:** correctness | **Confidence:** high | **Audit severity:** medium (adversarially confirmed)

**Suggested fix:** Drop the per-batch sort + unshift + final reverse entirely. Since Discord returns each batch newest-first and you page with `before: lastId` (strictly older each iteration), simply push each batch's IDs and at the very end build the array oldest-first once. Concretely: collect raw messages into one array via `all.push(...fetched.values())` per batch (newest-first overall), then do `all.sort((a,b) => a.createdTimestamp - b.createdTimestamp)` and map to formatMessage. One global sort by createdTimestamp is unambiguous and removes the interleaving.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0023. See audit/2026-05-31/full-codebase-audit.md.
