**Done 2026-05-31:** Upgraded vitest + @vitest/coverage-v8 + @vitest/ui 3.2.4 -> 4.1.7 (the trio must move together; @vitest/ui peer-pins the major). 44 failures across 9 files, all v4 breaking-change fallout, fixed without touching src/ or weakening assertions:

1. Arrow-function constructor mocks. v4 forbids `new` on an arrow-implemented mock ("is not a constructor"). Changed `vi.fn(() => obj)` / `.mockImplementation(() => obj)` to `function () { return obj; }` for mocked classes/builders (eventWrap WideEventBuilder, listopen LRUCache).
2. Mock implementations reset between tests. v4's `restoreMocks: true` now resets `vi.fn()` implementations (v3 only restored `vi.spyOn` spies), and `clearAllMocks` does not drain `mockReturnValueOnce` queues. Module-scope factory mocks overridden mid-suite (a throwing `db.prepare`, a queued cooldown `Once`, etc.) leaked into later tests. Fixed by re-establishing default implementations in `beforeEach` after the clear (listopen, purge, flaggerStore, ensure), and switching appLookup's `beforeEach` to `vi.resetAllMocks()` to also drain stale once-queues.
3. Stale `vi.mock` path. v4 resolves mock targets strictly; config.test.ts mocked the long-gone `src/utils/owner.js`. Repointed mock + import to the real `src/lib/owner.js` (a latent bug v3 silently tolerated).
4. Spy-reuse masking. messageDadMode/messageSkullMode were green in v3 only because `vi.restoreAllMocks()` nulled the `getConfig` mock so the handler bailed before rolling; with odds clamped to 1 the random spy never actually mattered. Set realistic odds (1000/10000) so the mocked `Math.random()=0.5` yields a genuinely non-zero roll, exercising the real no-react path. Assertions unchanged.

Verified: typecheck 0, 5455 tests pass, build success, `vitest run --coverage` passes thresholds under the v4 coverage-v8 provider.
