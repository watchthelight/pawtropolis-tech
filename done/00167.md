# #00167 -- Trace-ID tests assert behavior the source does not implement (interactionId.slice(-8))

**Type:** bug | **Priority:** Low

Tests 'generates trace ID from interaction ID', 'uses last 8 chars of interaction ID', and 'converts to uppercase' assert that the error trace id equals `interactionId.slice(-8).toUpperCase()`. The real modals.ts catch blocks compute `const traceId = ctx().traceId ?? newTraceId();` (modals.ts lines 66,104,143,182,272). newTraceId() (src/lib/reqctx.ts:39) returns an 11-char random base62 string and never touches the interaction id. So the documented/asserted trace-id derivation is simply false. Because the tests only exercise their own inline slice() expression they still pass, masking that (a) the real trace logic is untested and (b) the described behavior is wrong. Anyone reading the suite is misled about how trace ids are produced.

**Location:** `tests/features/review/handlers/modals.test.ts:76-87, 306-317`
**Category:** correctness | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Remove these trace-id-from-interaction tests, or rewrite them to mock src/lib/reqctx (ctx/newTraceId) and assert the handler logs/replies with the value returned by newTraceId()/ctx().traceId. Do not assert a slice of interaction.id.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0207. See audit/2026-05-31/full-codebase-audit.md.
