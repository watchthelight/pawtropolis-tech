# #00160 -- Env SILENT_FIRST_MSG_DAYS silently overrides an explicit per-guild DB value of exactly 7

**Type:** bug | **Priority:** Low

getFlaggerConfig uses silentDays === 7 as the sentinel for 'DB had no value' (lines 166-169). But 7 is also a valid, explicitly-settable per-guild value: setSilentFirstMsgDays accepts the range 7..365 (line 236) and 7 is the minimum allowed. If a guild deliberately sets silent_first_msg_days = 7 in guild_config and the SILENT_FIRST_MSG_DAYS env var is set to a different number (e.g. 30), the DB read sets silentDays = 7 (line 140-142), then line 166 sees silentDays === 7 and overwrites it with the env value (30). The guild's explicit choice is silently discarded, changing flagging behavior. The code comment itself flags this fragility ('this logic assumes 7 is the default').

**Location:** `src/config/flaggerStore.ts:159-170`
**Category:** correctness | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Track whether the DB actually supplied a value using a real sentinel instead of the magic number. e.g. let dbDays: number | null = null; set it from row.silent_first_msg_days when non-null; apply the env fallback only when dbDays === null; finally silentDays = dbDays ?? envDays ?? 7.
