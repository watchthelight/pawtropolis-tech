# #00096 -- Parallel '--no-tests' deploy path lacks lock/backup/health-check and duplicates the swallowed-migration bug

**Type:** bug | **Priority:** Medium

deploy-no-tests.sh is a second, fully independent deploy script targeting the same prod host/path/PM2 process as deploy.sh. It (a) repeats the exact swallowed-migration defect at line 25 (`node scripts/migrate-remote.js || echo "Migration step completed (may have warnings)"`), (b) has no deploy lock, so it can race a concurrent deploy.sh run (deploy.sh's mkdir lock at line 83 does not protect against this script, which never acquires it), (c) takes no pre-deploy DB backup, and (d) has only a best-effort `pm2 show | grep` status check with no Discord-ready verification. Two scripts mutating the same server with different safety guarantees is a cross-file hazard: an operator using this 'fast' path silently loses every protection that was added to deploy.sh in the 2026-05-02 hardening pass.

**Location:** `deploy-no-tests.sh:1-42`
**Category:** deploy-safety | **Confidence:** high | **Audit severity:** medium (adversarially confirmed)

**Suggested fix:** Delete deploy-no-tests.sh and fold its behavior into `deploy.sh --fast` (which already exists, lines 159-162), so there is exactly one hardened deploy path with the lock, backup, and migration-abort logic.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0292. See audit/2026-05-31/full-codebase-audit.md.
