# #00213 -- Cleanup setInterval is never unref'd or cleared - keeps the event loop alive (hangs tests/shutdown)

**Type:** bug | **Priority:** Low

At module load, rateLimiter.ts calls `setInterval(cleanupOldCooldowns, CLEANUP_INTERVAL_MS)` (10 min) and never calls `.unref()` on the returned timer, nor stores it for clearing, nor guards on a test env. By contrast, cmdWrap.ts (armWatchdog, line ~192) correctly does `timer.unref()`. A live, ref'd interval keeps the Node process alive. This is exercised by my bucket: tests/commands/listopen.test.ts imports src/commands/listopen.js, which imports rateLimiter (`checkCooldown`, `clearCooldown`, `COOLDOWNS`). The module's own comment even admits this: 'This interval is never cleared, so this module can't be cleanly unloaded ... If tests start hanging, this is why.' Impact: vitest workers may not exit cleanly (forces teardown timeout / --forceExit reliance), and in production it blocks graceful shutdown.

**Location:** `src/lib/rateLimiter.ts:149`
**Category:** leak | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Capture the handle and unref it, mirroring cmdWrap.ts: `const t = setInterval(cleanupOldCooldowns, CLEANUP_INTERVAL_MS); if (typeof t.unref === 'function') t.unref();`. Optionally export a `stopCleanup()` that clears it for deterministic test teardown.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0162. See audit/2026-05-31/full-codebase-audit.md.
