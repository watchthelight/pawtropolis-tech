# #00149 -- Server-side cached() defeats SSE live-refresh on pulse/stats; invalidate() is never called by any mutation

**Type:** bug | **Priority:** Medium

The two-tier cache exposes invalidate(key), but a repo-wide search shows it has ZERO callers anywhere in web/src (only the definition matches). Meanwhile the mutation API routes (/api/review/[action], /api/modmail/*, /api/config/update, etc.) mutate state through the bot and return without touching the cache. The Pulse page (web/src/routes/dashboard/pulse/+page.svelte:83-92) explicitly subscribes to review:*, modmail:*, flag:* and calls invalidateAll() on each event to deliver 'Live pulse updates'; the Stats page does the same on stats:updated. But the data those pages render comes from cached(guildKey, CACHE_TTL.medium=60_000, ...) (pulse) and cached(personalKey/teamKey, CACHE_TTL.medium, ...) (stats), keyed by rangeCacheKeyParts(range,60) whose minute bucket is stable inside any 60s window. So after a moderator approves an application: the DB changes, the SSE event arrives (~150ms debounce), invalidateAll() re-runs the server load, and cached() returns the SAME pre-mutation L1 object for up to ~60s. The counters (Pending Applications, Open Modmail, Decisions/Approvals, team leaderboard) visibly fail to update despite the live wiring, until the TTL lapses. The reviews queue itself is unaffected because its layout load (reviews/+layout.server.ts) is uncached.

**Location:** `web/src/lib/server/cache.ts:143-153 (definition); web/src/routes/api/review/[action]/+server.ts:55-85; web/src/routes/api/modmail/send/+server.ts:22-38; consumers web/src/routes/dashboard/pulse/+page.server.ts:37-45 and web/src/routes/dashboard/stats/+page.server.ts:39-57`
**Category:** caching / staleness | **Confidence:** high | **Audit severity:** medium (adversarially confirmed)

**Suggested fix:** Wire invalidate() into the mutation handlers (or invalidate by key prefix) so a review/modmail/flag/config mutation drops the matching pulse:*/stats:* cache entries. Since keys embed guildId + range bucket + (for personal) userId, add a small prefix-scan invalidation (e.g. track keys per namespace, or switch the L1 Map to allow deleting by startsWith('pulse:guild:'+guildId)). Alternatively, have the SSE-triggered reload pass a cache-busting flag the load honors. Minimum: call invalidate for stats:team:* and pulse:guild:* on any review/modmail mutation so the live refresh shows fresh counts.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0347. See audit/2026-05-31/full-codebase-audit.md.
