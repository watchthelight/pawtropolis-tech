# #00274 -- Test suite must not open data/data.db

**Type:** bug | **Priority:** High

Several test files import `src/db/db.ts` transitively and the module opens `DB_PATH || data/data.db` at import time, runs its `CREATE TABLE IF NOT EXISTS` bootstrap and sets pragmas on it. Locally that file is a 5 GB copy of production. The suite log shows `SQLite opened dbPath ./data/data.db` for those files.

**Fix:** `tests/setup.ts` sets `DB_PATH` to `tests/.tmp/vitest-<pid>.db` before any import and seeds it from `tests/fixtures/schema.sql` when the file does not exist; `tests/.tmp/` is ignored. Any test that relied on production-copy contents gets explicit fixture rows.

## Closed 2026-09-02

tests/setup.ts points DB_PATH at a per-worker temp file seeded from the fixture schema; nothing opens data/data.db any more.
