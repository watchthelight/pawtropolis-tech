# #00097 -- review_claim.claimed_at is written as an integer into a TEXT column, so normalizeTimestamp always returns null

**Type:** bug | **Priority:** Medium

review_claim.claimed_at is declared `TEXT NOT NULL` (src/db/db.ts:129-133 and tests/fixtures/schema.sql:766-770). The production writer reviewActions.ts:110 inserts `nowUtc()` (an integer, e.g. 1748000000) with a comment claiming it is 'matching both table schemas' -- but the column has TEXT affinity, so SQLite coerces the integer to the STRING '1748000000.0' (verified empirically with better-sqlite3). The reader getReviewQueue/getApplicationDetail passes claimed_at through normalizeTimestamp (shared.ts), whose string branch does `value.replace(' ','T') + 'Z'` -> '1748000000.0Z' -> new Date(...) -> NaN -> returns null. Verified: normalizeTimestamp('1748000000.0') === null. Net effect: ReviewQueueItem.claimedAt and ApplicationDetail.claimedAt are ALWAYS null in the dashboard, so reviewers never see when an application was claimed. This is masked by the test suite because the test fixture (tests/utils/dbFixtures.ts:334) inserts claimed_at as `new Date().toISOString()` (a real ISO string that normalizeTimestamp parses fine) -- the fixture does not match how production writes the column, so tests pass while production is broken.

**Location:** `web/src/lib/server/queries/reviews.ts:189, 456 (getApplicationDetail/getReviewQueue claimedAt) via web/src/lib/server/queries/shared.ts:4-20 and src/features/reviewActions.ts:108-114`
**Category:** NULL handling / cross-module type mismatch | **Confidence:** high | **Audit severity:** medium (adversarially confirmed)

**Suggested fix:** Make normalizeTimestamp recognize numeric strings (e.g. if `/^\d+(\.\d+)?$/.test(value)` treat it as a unix-seconds/ms number and reuse the numeric branch), OR change the writer to store ISO text via tsToIso(nowUtc()) into the TEXT column, OR migrate review_claim.claimed_at to INTEGER and store seconds. The numeric-string guard in normalizeTimestamp is the lowest-risk fix and also hardens every other TEXT-affinity timestamp reader.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0310. See audit/2026-05-31/full-codebase-audit.md.
