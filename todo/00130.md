# #00130 -- claimHandlers.test.ts never imports handleClaimToggle/handleUnclaimAction; tests assert only literals

**Type:** refactor | **Priority:** Medium

The file claims to test handleClaimToggle and handleUnclaimAction but never imports claimHandlers.ts and never calls either function. Each case rebuilds a string locally, e.g. line 72-75 `const msg = errorCode === "ALREADY_CLAIMED" ? "..." : "..."; expect(msg).toContain("already claimed")`, and the 'permanent rejection check' (line 110-112) asserts a hard-coded SQL string rather than that the handler actually runs that query. Consequently the real claim flow is untested: the post-claim permanently_rejected re-check (claimHandlers.ts:84-102), the ClaimError->message mapping, the assumption that the parent already called deferUpdate, and the audit/log/notify side effects. A regression (e.g. removing the perm-rejected block so a banned user can be claimed/approved) passes all assertions here.
