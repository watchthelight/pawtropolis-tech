# #00184 -- `--batch` with a missing/non-numeric value produces NaN and the LIMIT bind throws a datatype-mismatch

**Type:** bug | **Priority:** Low

`const MAX_BATCH = batchArg >= 0 ? parseInt(args[batchArg + 1], 10) : 5000;` If `--batch` is supplied without a following numeric value, `MAX_BATCH` becomes NaN, which is then bound as the `LIMIT ?` parameter at line 37. better-sqlite3 rejects NaN as an integer parameter with `SQLITE_MISMATCH: datatype mismatch`, so the cron-run aborts with an unhandled exception before doing any work. Fails safe (no corruption) but the scheduled context materialization silently stops making progress until someone notices the crashing cron job.

**Location:** `scripts/build-context-incremental.mjs:22-24, 37`
**Category:** correctness | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Guard the parse: `const n = parseInt(args[batchArg+1], 10); const MAX_BATCH = Number.isFinite(n) && n > 0 ? n : 5000;`

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0012. See audit/2026-05-31/full-codebase-audit.md.
