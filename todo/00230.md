# #00230 -- "preserves cause" test has a dead variable and does not test what its name claims

**Type:** refactor | **Priority:** Low

The test creates `const cause = new Error("root cause")` and assigns it as `err.cause`, implying it verifies the original cause chain is preserved by classifyError. But the only assertion is `expect(result.cause).toBe(err)` - it asserts the classified error's `.cause` is the wrapped error itself, never referencing the `cause` variable. Per the source (src/lib/errors.ts:234, `cause: err instanceof Error ? err : undefined`), classifyError stores the passed-in error as `.cause` and silently discards any nested `err.cause` (the real root cause). So the `cause` local on line 237 and the assignment on line 239 are dead, and the test gives false confidence that cause-chain information survives classification when it does not. Impact: a future change that (correctly) starts unwrapping `err.cause` would not be caught here, and the misleading test name hides that root-cause data is dropped during error classification.

**Location:** `tests/lib/errors.test.ts:236-243`
**Category:** dead-code | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Either rename the test to "stores the original error as cause" and remove the unused `cause` variable/assignment, or (if cause-chain preservation is actually desired) change the source to walk `err.cause` and update the assertion to `expect(result.cause).toBe(cause)`.
