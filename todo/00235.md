# #00235 -- "timestamp is NaN" test does not exercise the NaN guard it claims to cover

**Type:** bug | **Priority:** Low

The test builds its body as `{ ...validEvent, timestamp: NaN }` (the `body` path, not `rawBody`). makeEvent serializes it via JSON.stringify, and JSON.stringify converts NaN to `null` (verified: JSON.parse(JSON.stringify({timestamp:NaN})).timestamp === null, typeof === 'object'). So by the time the handler (web/src/routes/api/internal/events/+server.ts) parses the body, `event.timestamp` is null. The handler returns 400 via the `typeof event.timestamp !== "number"` branch (line 67) - the same branch the "timestamp is not a finite number" test ('yesterday' string) already covers. The dedicated `!Number.isFinite(event.timestamp)` guard (line 68) therefore has ZERO test coverage from this suite: no test ever feeds the handler a value that is a number but non-finite. A regression that deletes the `!Number.isFinite(...)` check (e.g. allowing Infinity, which a buggy bot serializer or a non-JSON caller could send) would not be caught. The test passes, giving false confidence.

**Location:** `tests/web/routes/internal.events.test.ts:115-123`
**Category:** correctness | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Drive the handler with a raw body so NaN/Infinity survive to the parser, e.g. `evt({ secret: SECRET, rawBody: JSON.stringify({...validEvent, timestamp: 1}).replace('1','Infinity') })` or post a literal `{"type":"x:y","timestamp":Infinity,"payload":{}}` as rawBody (note: invalid JSON, so instead inject via a number that bypasses stringify). Simplest: add a case that posts rawBody `'{"type":"x:y","payload":{},"timestamp":1e999}'` (1e999 parses to Infinity) and assert 400; that actually exercises the Number.isFinite branch.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0232. See audit/2026-05-31/full-codebase-audit.md.
