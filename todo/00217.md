# #00217 -- 'CSV contains correct header row' test asserts nothing about the header

**Type:** refactor | **Priority:** Low

The test is named 'CSV contains correct header row' and includes the comment 'AttachmentBuilder stores the data - need to access it', but the only assertion is `expect(attachment).toBeDefined()`. It never decodes the AttachmentBuilder buffer nor checks the header string. The handler (src/commands/stats/export.ts L116) emits a specific header 'Moderator ID,Total Decisions,Approvals,...'; if that header were reordered, renamed, or dropped, this test would still pass. It provides no protection for the behavior its name claims.

**Location:** `tests/commands/stats/export.test.ts:200-209`
**Category:** dead-code | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Read the attachment payload (e.g. `(attachment.attachment as Buffer).toString('utf-8')`) and assert it `.startsWith('Moderator ID,Total Decisions,Approvals,Rejections,Modmail,Perm Reject,Kicks,Avg Response Time (seconds),Avg Response Time (formatted)')`, plus assert a sample data row is present. Or delete the test if redundant.
