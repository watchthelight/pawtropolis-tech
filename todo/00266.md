# #00266 -- Perf pass T4: startup, process, dependencies, deploy

**Type:** refactor | **Priority:** Medium | **Status:** `WIP`

Fifth tier of the performance plan.

**Items**

1. Startup order: parallel groups after the member fetch; schema self-heal and short-code sync deferred past ready.
2. `canvas` and `sharp` loaded lazily inside the commands that render images; heatmap buckets in SQL.
3. Sentry profiling only when `SENTRY_PROFILES_SAMPLE_RATE > 0`; `.env.example` defaults `LOG_LEVEL=info`, `SENTRY_TRACES_SAMPLE_RATE=0.05`; async pino destination in production.
4. Owner decision: drop the `GuildPresences` intent, use approximate presence count. `MessageManager` 200 -> 50 with explicit sweepers.
5. Dependencies: `@types/node` to dev; remove unused `@google-cloud/vision`, `@sveltejs/adapter-auto`, `mermaid`, `d3` if the builds pass; `precompress: true` for adapter-node.
6. dbRecovery streams checksums instead of reading whole backups into memory.
7. Badge endpoint serves SVGs from memory with an ETag.

**Update 2026-09-01:** landed in six commits (d7eb5b8b through 9edad636): concurrent REST warm-ups after modmail hydration, message cache 200 -> 50 with a 10 min sweeper, optimize before close and log flush on exit, async pino stdout, profiling behind `SENTRY_PROFILES_SAMPLE_RATE`, lazy canvas and sharp, dependency cleanup, badge cache, streamed checksums. Still open: the `GuildPresences` intent is unchanged (owner decision: the dashboard profile card shows presence today); schema self-heal and the short-code sync still run inline at boot (both are cheap PRAGMA probes and INSERT OR IGNORE); `tsx` stays a production dependency because the migration runner and the PM2 backfill app run TypeScript directly; tsup minify and nginx compression were not touched.
