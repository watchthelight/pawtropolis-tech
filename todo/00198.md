# #00198 -- Env fallback overrides a guild's explicitly-configured silent_first_msg_days when the configured value equals 

**Type:** bug | **Priority:** Low

getFlaggerConfig uses `silentDays === 7` as a sentinel meaning "DB had no value" (lines 166-169). But 7 is also a fully valid value a guild can persist: setSilentFirstMsgDays accepts the range 7-365 (line 236), so a guild can explicitly set 7. When such a guild exists AND process.env.SILENT_FIRST_MSG_DAYS is set to a different number (e.g. 30), the DB-provided 7 is silently clobbered by the env value, ignoring the guild's explicit configuration. The comment on lines 162-163 even acknowledges the fragility. Trigger is narrow (guild explicitly set the boundary value 7 while a differing env default is present), hence low severity, but the resolution logic is genuinely incorrect.

**Location:** `src/config/flaggerStore.ts:165-170`
**Category:** correctness | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Track whether the DB actually supplied a value with a separate boolean (e.g. `let dbHadDays = false;` set inside the `row.silent_first_msg_days !== null` branch) and only apply the env fallback when `!dbHadDays`, instead of overloading the magic number 7.
