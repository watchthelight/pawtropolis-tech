# #00127 -- Local BUTTON_RE diverges from the real BTN_DECIDE_RE it claims to test, giving false coverage of the review bu

**Type:** bug | **Priority:** Medium

The `describe("BUTTON_RE pattern")` block defines its OWN regex `const BUTTON_RE = /^v1:decide:(\w+):code([0-9A-F]{6})$/;` and asserts against it. The production symbol it purports to cover is `src/features/review/handlers/helpers.ts:38` `export const BUTTON_RE = BTN_DECIDE_RE;`, which resolves to `src/lib/modalPatterns.ts:35`: `/^(?:v1:decide|review):(approve|accept|reject|kick|claim|unclaim|wrong_password|stale_modmail):code([0-9A-F]{6})$/`. The two differ materially: (1) the test uses `(\w+)` for the action, accepting ANY word, whereas production restricts to a fixed allowlist; (2) the test omits the `review:` prefix alias that modalPatterns.ts explicitly keeps for weeks-old button embeds. Because the test never imports the real regex, a regression in BTN_DECIDE_RE (e.g. dropping `kick` from the allowlist, or removing the `review:` alias) would NOT fail any of these tests. The button router gates moderation actions (approve/reject/kick/claim), so this is security-relevant code with effectively zero regression protection from this suite.

**Location:** `tests/features/review/handlers/helpers.test.ts:191-258`
**Category:** correctness | **Confidence:** high | **Audit severity:** medium (adversarially confirmed)

**Suggested fix:** Import the real constant instead of redefining it: `import { BUTTON_RE } from "../../../../src/features/review/handlers/helpers.js";` (or import `BTN_DECIDE_RE` from `src/lib/modalPatterns.js`) and assert against that. Add cases proving the action allowlist is enforced (e.g. `v1:decide:bogus:codeABCDEF` must NOT match) and that the `review:` prefix alias matches.
