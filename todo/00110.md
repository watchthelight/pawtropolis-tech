# #00110 -- ensureGateEntryStartup iterates pinned MessagePin objects as if they were Message objects, so pinned gate pane

**Type:** bug | **Priority:** Medium

fetchPins().items is `readonly MessagePin[]` where MessagePin = { message, pinnedAt, pinnedTimestamp } (typings 6586-6590). The startup code does `const pinnedCollection = (pinned as { items?: { values: () => Iterable<Message> } }).items;` then `for (const m of pinnedCollection.values()) candidates.set(m.id, m);`. Array.prototype.values() yields the elements, which are MessagePin objects, NOT Message objects. So `m.id` is undefined (every pinned entry is keyed under the same `undefined` slot in the candidates Map) and `m` has no `.components`/`.embeds`. The later guard `if (!Array.isArray(m.components) || !Array.isArray(m.embeds)) continue;` (line 263) is therefore always true for these entries, so the pinned branch contributes nothing. Impact: the startup foreign-bot-panel cleanup and current-bot pinned-panel reuse never see pinned messages; after a bot-identity swap an old foreign pinned panel can be missed, and a current pinned panel may be re-posted instead of edited. The recent-50 fetch at line 256 partially masks this (the panel is usually also in recent history), so it limps along rather than fully failing.

**Location:** `src/features/gate/entryPanel.ts:250-256`
**Category:** correctness | **Confidence:** high | **Audit severity:** medium (adversarially confirmed)

**Suggested fix:** Iterate items as a plain array of MessagePin and use the inner message: `const items = (pinned as { items?: ReadonlyArray<{ message?: Message }> }).items; if (Array.isArray(items)) { for (const it of items) { const m = it?.message; if (m) candidates.set(m.id, m); } }` - matching findExistingGateEntry in the same file.
