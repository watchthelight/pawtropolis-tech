# #00220 -- Failure message reports un-stripped matches (includes allowed code-block mentions), confusing diagnostics

**Type:** bug | **Priority:** Low

The assertion correctly uses `realMatches` (mentions after fenced code blocks are stripped, lines 91-92), but the error message interpolates `matches` (line 89/95), which is computed against the FULL text including code blocks. If a file legitimately contains mention syntax inside a ``` fenced block AND also has a real violation outside it, the failure message will list the code-block mentions too, sending the developer to lines that are actually allowed. If a file's only mentions are inside code fences, realMatches is empty so the test passes (correct) - but `matches` would be non-empty, which is harmless only because the message isn't shown on pass. This is a diagnostics defect, not a guard-correctness defect.

**Location:** `tests/docs/badgeDocsIntegration.test.ts:89-99`
**Category:** correctness | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Interpolate `realMatches.join(", ")` (not `matches`) into the failure message so the reported mentions are exactly the ones that caused the failure.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0183. See audit/2026-05-31/full-codebase-audit.md.
