# #00262 -- Perf pass T0: unblock the event loop and stop timer leaks

**Type:** refactor | **Priority:** High | **Status:** `WIP`

First tier of the performance / latency / RAM plan (full plan with file:line evidence lives in the Claude plan file `optimized-nibbling-crane.md`). Everything here is behaviour-preserving except the cadence changes called out.

**Items**

1. opsHealth: `PRAGMA quick_check` ran on the bot connection every 60 s (`src/features/opsHealth.ts`), and `pm2 jlist` was spawned every 60 s (`src/lib/pm2.ts`). quick_check moves to a child process on a 6 h cadence (`src/lib/dbIntegrityCheck.ts`, `src/scheduler/dbIntegrityScheduler.ts`); PM2 status is cached 60 s and polled every 15th tick.
2. `wrapEvent` and `approve.ts withTimeout` never cleared their race timers, retaining handler args for 10 s / 30 s per event.
3. Startup integrity check defaults to `quick` in production (`ecosystem.config.cjs`, `src/lib/dbHealthCheck.ts`).
4. Security audit used `guild.members.fetch()` (full gateway re-chunk) every 30 min; now reads the member cache, runs every 6 h, and skips docs/snapshot/history writes when nothing changed. Same cache substitution in levelStats, artistqueue, threadGate.
5. Reaction archive fetched every partial reaction over REST before recording fields already present on the partial.
