# #00290 -- Google web detection as a lookup in /investigate-artist

**Type:** feat | **Priority:** Medium

Owner decision 1 (#00287): "Both + google's web detection". Besides SauceNAO and e621, `/investigate-artist` gets Google's web detection (Cloud Vision, feature `WEB_DETECTION`) as a reverse image lookup. It finds pages and copies of an image on the open web, which the two art archives do not cover.

- Uses the Google Vision key of #00289. Without a key the lookup is skipped and the report names it as skipped, like the others.
- Results go through the same cache and the same report section as the other lookups.
- Google bills this feature per image, so the report says how many images were sent.

What was built:

- `src/features/artistInvestigation/provenance/googleWeb.ts`, a fourth lookup service next to Fluffle, e621 and SauceNAO. It sends one request per image and never a mirrored copy, because every image sent is billed.
- A page that Google lists with the whole image is an "exact" match. A page with a part of the image or an edited copy is "probable". Copies of the file that are on none of the listed pages are added too, four at most. Google's look-alike images, labels and entities are not used.
- Google names no artist and no post date. The name check goes by the account name in the page's address where the site is one the command can read, and says "nothing to compare" otherwise. A tweet's date is read from its address.
- Ranking. Six matches are listed per image. Google's first four for an image are ranked with the others by quality. Any further ones go last, so a picture that is all over the web cannot push the art archives' matches off the list. When Google and an archive find the same page, the archive's entry stays, because it names the artist.
- Google's matches are left out of the "names N different artists" note. That note is about look-alikes, and one picture reposted under several accounts is not that.
- The report and the model are both told what "exact" and "probable" mean for a Google match.
- A refused request shows the HTTP status and Google's reason code. Google's own sentence is not passed on, because it can name the project.

Cost: the first 1000 images a month are free, then 3.50 USD per 1000 (Cloud Vision pricing page, read on 2026-11-15). Google bills it to the project behind the key. It is not in the report's footer and not counted against `INVESTIGATE_MONTHLY_CAP_USD`.

Could not be checked: a real answer with matches. Google refuses the production key (HTTP 403, reason code `ACCESS_DENIED`, seen on 2026-11-15), so the reading of an answer follows Google's published response format and has only run against stubbed answers. What was run against the live service: the adapter with a key that cannot exist, which Google refused as expected.

Needs billing switched on and the Cloud Vision API enabled for the Google Cloud project behind the key, like the avatar scan.
