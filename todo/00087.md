# #00087 -- Migration failure is swallowed by `|| echo`, so the bot restarts against an un-migrated schema

**Type:** bug | **Priority:** High

The full deploy runs migrations as: `ssh_remote "cd ${REMOTE_PATH} && node scripts/migrate-remote.js" || echo "Migration step completed (may have warnings)"`. The migration runner scripts/migrate.ts is correctly designed to fail hard: on any migration error it logs and calls `process.exit(1)` (migrate.ts:308-311), and scripts/migrate-remote.js propagates that exit code via `process.exit(result.status || 0)` (migrate-remote.js:24). The `|| echo` in deploy.sh defeats that contract: a non-zero exit (e.g. a migration that throws, a SQLITE_BUSY because the old bot still holds data.db, or migrate-remote.js failing to find tsx) is converted to success. The deploy then proceeds to Step 6.6 (command registration) and Step 7 (`pm2 startOrRestart ecosystem.config.cjs`), starting the NEW code against the OLD schema. Because some migrations are destructive/structural (035_drop_unused_tables DROP TABLE, 028 and 067 DROP TABLE under conditions, 047/053 ADD COLUMN), the new bot can crash-loop on missing columns/tables or read a half-migrated DB. The operator only sees a soothing 'may have warnings' line. This is the central cross-file defect: deploy.sh trusts a wrapper whose carefully-propagated failure signal it then throws away.

**Location:** `C:/Users/Claude-Code/pawtropolis-tech/deploy.sh:433-435`
**Category:** deploy-safety/error-masking | **Confidence:** high | **Audit severity:** high (adversarially confirmed)

**Suggested fix:** Do not swallow the migration exit code. Capture it and abort the deploy before restarting PM2, e.g.: `if ! ssh_remote "cd ${REMOTE_PATH} && node scripts/migrate-remote.js"; then echo 'ERROR: migrations failed, aborting before restart' >&2; exit 1; fi`. The acquire_deploy_lock EXIT trap will still release the lock. If a 'warnings are tolerable' mode is genuinely wanted, gate it behind an explicit flag rather than making it the default.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0351. See audit/2026-05-31/full-codebase-audit.md.
