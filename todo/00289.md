# #00289 -- Service keys set from Discord

**Type:** feat | **Priority:** High

Owner decisions 1 and 16 (#00287): the keys of the outside services are to be settable from Discord, so they no longer have to be put into the host's `.env` by hand. In the owner's words: "Make a way for this key to be configured discord-side".

Covers the Google Vision key (avatar scan, `/audit nsfw` and the web detection of #00290), the SauceNAO key, and the e621 login and key.

What it needs:

- An owner-only command. The key is typed into a modal and the answer is ephemeral, so it never shows in a channel.
- Storage in the database, encrypted. A key in plain text would be readable by the dashboard, which opens the same file, and would sit in every backup.
- A key set from Discord wins over the one in the environment. The environment stays as the fallback, so nothing changes for a host that has its keys there.
- A status view that says which service has a key, where it comes from and who set it when, and never shows a value.
- A test call per service, so a key that the service refuses is seen at once.

Setting the Vision key this way does not change what Google answers today (403, "This API method requires billing to be enabled"). Billing has to be on for the Google Cloud project behind the key.
