## Update 2026-09-02 (after the 6.2.0 deploy)

**Log truth:** the live pm2 files are `pawtropolis-out-7.log` / `pawtropolis-error-7.log`; the `pawtropolis-out.log` the baseline was read from is a stale file from an earlier process id (its window runs from May). Across all files before the deploy: 61 `slow_transaction` lines, max 13157 ms, 11529 warn-level lines (9406 of them the Google Vision 403 "billing not enabled" warning, one per member join). Noisiest debug events (`level_role_not_configured` 79k, dadmode checks 62k, activity flushes 60k) are debug level and disappear at `LOG_LEVEL=info`.

**Since the deploy (first 20 minutes):** 0 slow transactions, 0 handler timeouts, 0 loop lag warnings, 0 warn or error lines; bot RSS 222 MB (262 before), web RSS 96 MB (404 before), data.db 1210 MB with a 1.5 MB WAL (1636 MB and 180 MB before), disk 52% (83% before). The 24 h numbers go in the table once available.

**Static sweep results:** no `members.cache.filter` or `role.members` scans remain on hot paths; `guild.members.fetch(id)` and `client.users.fetch(id)` sites are cache-first in discord.js and stay; no per-event `JSON.parse` or `new RegExp` in `src/events`; dashboard COUNT queries over `message_activity` and `action_log` run under `cached()` with windowed indexes (`idx_message_activity_guild_time`, `idx_action_log_guild_time`) and stay; `api/art/uploads/[...path]` reads whole files but they are 800 px WebP thumbnails and stays. Google Vision now pauses itself for 6 hours after a 403 or 429 instead of failing every join.

**Lighthouse (desktop, 2026-09-02):** `/observatory` 93 (LCP 1.6 s, TBT 0, CLS 0), `/changelog` 90 (LCP 1.6 s, CLS 0.023), `/handbook` 85 (LCP 1.6 s, TBT 0, CLS 0.142). The handbook score is the layout shift; see the fix note below once landed.
