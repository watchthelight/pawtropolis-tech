# #00194 -- invalidatePermissionCache is never called from production code, so the documented 'call this when roles change

**Type:** refactor | **Priority:** Low

invalidatePermissionCache() is exported and unit-tested, and the comment at cache.ts:206-207 explicitly states it must be called when a user's roles change to avoid serving a stale command list. A repo-wide search shows it is referenced only by its own definition/comment and the test file - never by any role-change path (no guildMemberUpdate handler, role automation, or config update calls it). Combined with the cache-key issue above, any role change (e.g., a user promoted to reviewer) is not reflected in /help for up to 5 minutes. Impact is limited to help-display accuracy, so low severity, but the function is effectively dead and the invariant it guards is not enforced.

**Location:** `src/commands/help/cache.ts:322-327`
**Category:** dead-code | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Call invalidatePermissionCache(guildId, userId) from the member/role update path (e.g., guildMemberUpdate when roles change) and from config changes that affect mod_role_ids/reviewer_role_id, or document that staleness up to CACHE_TTL_MS is accepted and remove the misleading 'call this' comment.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0049. See audit/2026-05-31/full-codebase-audit.md.
