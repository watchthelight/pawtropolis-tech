# #00164 -- DM verification sessions are looked up by userId only, ignoring guildId, so a user in two bot guilds gets cros

**Type:** bug | **Priority:** Low

Sessions are stored keyed by `${guildId}:${userId}` (sessionKey, line 83-85; activeSessions.set at 326) but hasActiveSession(userId) (87-92) and getSessionForUser(userId) (94-99) scan only by session.userId and return the FIRST match. messageCreate.ts:154-156 and interactionCreate.ts routing call these with only the author/user id. The bot is explicitly multi-guild (startup/ready.ts and several schedulers loop over client.guilds.cache). Consequences for a user who is in two guilds where the bot lives: (a) startDmVerification's duplicate guard at line 191 keys by guild+user, so it WILL create a second session for guild B while guild A's session exists, but getSessionForUser then returns whichever was inserted first - a DM answer intended for guild B can be persisted against guild A's appId via upsertAnswer (handleDmAnswer line 380), and the Submit button resolves to the wrong guild's application; (b) only one of the two verifications is reachable via DM at a time. This is data-integrity-relevant (answers written to the wrong application) though it requires the dual-guild precondition.

**Location:** `src/features/gate/dmVerification.ts:87-99`
**Category:** correctness | **Confidence:** medium | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Key all session operations by guild+user. Either thread guildId through the message/button routing (parse it from the active session's stored thread/guild, or include it in the button customId which already carries a nonce) and look up via activeSessions.get(sessionKey(guildId,userId)), or at minimum disallow more than one active session per user globally and tie the DM answer to the single session deterministically. The nonce on the buttons already scopes button actions, but text-answer routing (handleDmAnswer) has no guild scoping at all.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0083. See audit/2026-05-31/full-codebase-audit.md.
