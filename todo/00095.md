# #00095 -- Migration runner reports success when the child is killed by a signal (result.status null)

**Type:** bug | **Priority:** Medium

spawnSync returns { status, signal }. When the child tsx process is terminated by a signal (e.g. OOM-killer during a large migration, or SIGTERM from pm2/kill_timeout), `result.status` is null and `result.signal` is set. `process.exit(result.status || 0)` then exits 0, reporting success for a migration that never completed. Even when status is a real non-zero, the upstream caller in deploy.sh:435 throws the code away via `|| echo`, but this line independently masks signal kills for ANY caller (deploy-no-tests.sh:25, docs/development-guide.md:175 step 7, manual runs). Combined with the swallowed-exit bug it means a killed migration looks fully successful end to end.

**Location:** `scripts/migrate-remote.js:18-24`
**Category:** deploy-safety | **Confidence:** high | **Audit severity:** medium (adversarially confirmed)

**Suggested fix:** Propagate failure faithfully: `if (result.error) { console.error(result.error); process.exit(1); } process.exit(result.signal ? 1 : (result.status ?? 1));`. Use `?? 1` (not `|| 0`) so a null status fails closed.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0290. See audit/2026-05-31/full-codebase-audit.md.
