# #00185 -- Unguarded .get().sql throws opaque TypeError when source table is absent

**Type:** bug | **Priority:** Low

Line 13 does src.prepare(`SELECT sql ... name='general_messages_embed'`).get().sql. If the table does not exist in the source DB, .get() returns undefined and .sql throws 'Cannot read properties of undefined (reading sql)' with no context. The sibling export-processed.mjs handles this gracefully with `?.sql` + a 'skip (not found)' message (lines 29-30). export-score.mjs and export-substantiveness.mjs share the identical defect on their line 13. Impact is limited to operator confusion on a misconfigured/empty snapshot DB; data is not corrupted.

**Location:** `scripts/export-embed.mjs:13`
**Category:** correctness | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Use optional chaining and a clear error/skip: `const row = src.prepare(...).get(); if (!row?.sql) { console.error('table general_messages_embed not found in', SRC); process.exit(1); } dst.exec(row.sql);` - matching export-processed.mjs.
