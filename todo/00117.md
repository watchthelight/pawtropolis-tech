# #00117 -- Modal error replies overwrite the public review card content instead of being ephemeral

**Type:** bug | **Priority:** Medium

Each modal handler calls interaction.deferUpdate() (e.g. lines 49-53, 87-91, 126-130, 165-169, 203-207, 242-246) before doing work, so interaction.deferred is true. On the error paths these handlers call replyOrEdit(interaction, { content: 'Failed to process ... (trace: <id>).' }) with no flags, which takes the editReply branch in src/lib/cmdWrap.ts:503-506 and PATCHes the card's '@original' message -- replacing the review card's content line with the failure/trace text visible to the whole channel. The unclaim-cancelled branch (modals.ts:258-265) additionally passes flags: MessageFlags.Ephemeral, which is then stripped by replyOrEdit, so 'Unclaim cancelled. You must type UNCLAIM...' is shown publicly on the card too. Result: a transient handler error visibly corrupts the shared card content for all moderators.

**Location:** `src/features/review/handlers/modals.ts:69-73, 107-111, 146-150, 184-188, 223-227, 259-265, 275-279`
**Category:** correctness | **Confidence:** high | **Audit severity:** medium (adversarially confirmed)

**Suggested fix:** On these post-deferUpdate error paths, use interaction.followUp({ content, flags: MessageFlags.Ephemeral }) so the failure notice is a separate ephemeral message and the card content is left intact.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0120. See audit/2026-05-31/full-codebase-audit.md.
