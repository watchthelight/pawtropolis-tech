# #00091 -- /gate reset wipes ALL guilds' data, not just the current guild

**Type:** bug | **Priority:** Medium

In executeReset -> 'wipe_tables', the deletes are unscoped: runDelete("DELETE FROM application"), "DELETE FROM application_response", "DELETE FROM review_action", "DELETE FROM modmail_bridge", "DELETE FROM review_card", "DELETE FROM avatar_scan", "DELETE FROM review_claim" all run with no WHERE guild_id clause. These tables carry a guild_id column (confirmed in db schema / migrations / test fixtures: application.guild_id NOT NULL). The very next step, 'wipe_guild_question' (line 397-411), IS correctly scoped with "DELETE FROM guild_question WHERE guild_id = ?", and the confirmation modal customId is guild-scoped (v1:gate:reset:${guildId}). So the intent is clearly a per-guild reset, but the bulk deletes nuke every guild's applications/responses/actions/modmail bridges/claims that share this SQLite file. Any second guild (e.g. a staging/test guild, or future multi-tenant use) loses all of its gate data when a mod in one guild runs reset. The bot uses guild_id pervasively and supports per-guild config, so this is a genuine multi-guild data-loss bug; even in the current single-prod-guild deployment it is a latent footgun that diverges from the scoped questions wipe.

**Location:** `src/commands/gate/gateMain.ts:368-395`
**Category:** data-integrity | **Confidence:** high | **Audit severity:** medium (adversarially confirmed)

**Suggested fix:** Scope every delete by guild_id, mirroring the questions wipe. e.g. db.prepare('DELETE FROM application WHERE guild_id = ?').run(guildId); for review_action/modmail_bridge/review_card/avatar_scan/review_claim which key off app_id, delete via subquery: DELETE FROM review_action WHERE app_id IN (SELECT id FROM application WHERE guild_id = ?). Run application delete last (or capture app ids first) so the subqueries still resolve, all inside the existing transaction.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0037. See audit/2026-05-31/full-codebase-audit.md.
