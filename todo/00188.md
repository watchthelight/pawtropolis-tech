# #00188 -- Non-idempotent insert with fixed audit_run_id double-counts on re-run

**Type:** bug | **Priority:** Low

auditRunId is the hardcoded constant "audit-20260112-manual" (line 7). Each finding is written via insertFinding(...) which runs a plain INSERT into audit_findings; that table (migrations/043_audit_findings.ts) has only an AUTOINCREMENT primary key and NO unique constraint on (audit_run_id, command_name, subcommand). Re-running the script therefore inserts a second full copy of every finding under the same run id. generateReportData() then aggregates by audit_run_id, so totalCommands, passCount, skipCount, etc. (and the generated markdown report) silently double (or triple) for that run. The script also has no pre-delete of the existing run. Impact is limited because this is a manual one-shot script, not a runtime path.

**Location:** `scripts/record-audit-findings.ts:7,108-131,137`
**Category:** data-integrity | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Before inserting, delete existing rows for the run (DELETE FROM audit_findings WHERE audit_run_id = ?) inside a transaction, or add a UNIQUE(audit_run_id, command_name, subcommand) index and use INSERT ... ON CONFLICT DO UPDATE. At minimum, derive auditRunId from a timestamp at runtime so each run is distinct.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0025. See audit/2026-05-31/full-codebase-audit.md.
