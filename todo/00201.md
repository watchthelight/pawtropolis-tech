# #00201 -- Non-null assertion on a possibly-undefined Guild passed to logActionPretty (guild!) drops the audit-log entry 

**Type:** bug | **Priority:** Low

guild is obtained via interaction.client.guilds.cache.get(session.guildId) (line 534), typed Guild | undefined, and the `if (guild)` block (535-538) explicitly handles the undefined case for member fetch. But at line 565 logActionPretty(guild!, ...) uses a non-null assertion. logActionPretty immediately dereferences guild.id synchronously (src/logging/pretty.ts:488) with no undefined guard. If the guild is not in cache at submit time (sharding eviction, large-guild lazy cache), guild is undefined and logActionPretty rejects with TypeError. It is an async function so the throw becomes a rejected promise caught by the `.catch()` at line 571 - so no crash, but the gate_submit audit-log row is silently never written and only a warn is logged. The `!` hides a genuinely possible undefined.

**Location:** `src/features/gate/dmVerification.ts:534-571`
**Category:** types | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Guard before logging: `if (guild) { await logActionPretty(guild, {...}).catch(...); }` (you already fetched/checked guild above), or change logActionPretty to accept Guild | undefined and no-op when absent. Do not use `!` here.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0085. See audit/2026-05-31/full-codebase-audit.md.
