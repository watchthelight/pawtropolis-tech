# #00286 -- Deferred from v26: major upgrades and audit findings for the next release

**Type:** chore | **Priority:** Medium

Everything the v26 audit found and did not ship, with the reason for each, is in `MODERNIZATION_PLAN.md` section 3, Tier 3.

Largest items: Sentry 11, zod 4, vitest 5, eslint 10, TypeScript 7, the SvelteKit 3 and Vite 8 dashboard upgrade, better-sqlite3 13 (needs Node 22 or newer on the host), server-side dashboard sessions (SEC-4), in-handler permission checks for every command (SEC-6), database restore of a live WAL file (REL-5), stats refresh inside one write transaction (PERF-2), `setDMPermission` deprecation (HEALTH-6).

Added at the end of the v26 work:

- The mechanical format commit for the 819 older files (HEALTH-3): first give `*.cjs`, `*.css`, `*.html` and `.prettierrc` an `eol=lf` rule in `.gitattributes`, because a Windows clone checks them out with CRLF and prettier rejects that. Then run `npm run format`, commit it alone, add that commit to `.git-blame-ignore-revs`, and remove `continue-on-error` from the format step in `.github/workflows/ci.yml`.
- PERF-5, member join and leave handlers that wait on a log send: needs timing from production before it can be called an optimization.
- SEC-13, a host allow-list and a size cap for the ticket attachment mirror.
- eslint 10 ahead of the other tooling majors: eslint 9 is marked unsupported upstream.
- Typecheck `tests/`: two shared helpers alone report 21 errors.
- The host has run Node 24 since 2026-11-15 (#00293). Once the way back to Node 20 is given up (`/home/ubuntu/node20-rollback/` on the host): drop the Node 20 test leg from CI, raise the `engines` floor and the build target, and move better-sqlite3 forward.
- HEALTH-22, found in the production log after the deploy: `src/features/levelRewards.ts` logs a field named `level`, which replaces pino's own level, so "User leveled up to N" lines carry level N. Done in 26.1.0. It was thirteen log calls in three files, and one of them is the error line for a reward that could not be granted. The fields are renamed (`levelNumber`, and `alertLevel` in the disk space alert), and lint refuses a new one.
