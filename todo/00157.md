# #00157 -- Mutating staff subcommands never defer and await a network audit-log post before first ack, risking 10062

**Type:** bug | **Priority:** Low

Slash commands are dispatched by interactionCreate.ts:265 via `executor(interaction)` with NO auto-defer (wrapCommand only catches errors and posts an error card). handleAssign, handleCancel, and handleReassign never call deferReply(); they perform the DB write and then `await logActionPretty(...)` BEFORE the first interaction acknowledgement (handleCancel: audit_log at ~1136 precedes reply at ~1151; handleReassign: audit_log at ~1242 precedes reply at ~1259; handleAssign: audit_log at ~959 precedes reply at ~972). logActionPretty (src/logging/pretty.ts:464,517,635) calls getLoggingChannel(guild) and `channel.send({...})` - a network POST to Discord. If that post is slow (rate limit, transient latency), the total time from interaction receipt can exceed Discord's ~3s response window, so the subsequent interaction.reply() fails with 10062 (Unknown interaction). The DB mutation (cancel/reassign/create) has already committed, but the staff member sees 'This interaction failed' and wrapCommand then also tries (and fails) to post an error card. By contrast the read-only subcommands (handleJobs, handleAll, handleLeaderboard, handleGetStatus) all correctly deferReply() first.

**Location:** `src/commands/art.ts:895-994 (assign), 1072-1173 (cancel), 1182-1282 (reassign)`
**Category:** discord-api-misuse | **Confidence:** medium | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Call `await interaction.deferReply()` at the top of handleAssign/handleCancel/handleReassign (before the DB work / audit log), and replace the final `interaction.reply(...)` with `interaction.editReply(...)`. Alternatively, reorder so the user is acked first and the audit-log post is fire-and-forget after replying.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0032. See audit/2026-05-31/full-codebase-audit.md.
