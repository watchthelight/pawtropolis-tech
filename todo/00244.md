# #00244 -- Modmail thread list runs 2 correlated subqueries per row and is recomputed on every modmail navigation (uncach

**Type:** bug | **Priority:** Low

getModmailThreads() (called uncached from dashboard/modmail/+layout.server.ts:13 on every navigation) selects, per ticket row, two correlated subqueries that each re-scan modmail_message for the same ticket ordered by created_at DESC LIMIT 1 (latest_message at 55-56, latest_direction at 57-58) in addition to the LEFT JOIN+GROUP BY used for message_count. That is two redundant ordered lookups per ticket on top of the aggregate; both pull the same 'latest row'. Bounded by LIMIT 50 so impact is modest, but it is pure repeated work executed on every layout load.

**Location:** `web/src/lib/server/queries/modmail.ts:37-88`
**Category:** perf | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Fetch the latest message once per ticket via a window function (ROW_NUMBER() OVER (PARTITION BY ticket_id ORDER BY created_at DESC)) joined to the ticket aggregate, returning content+direction in a single pass. Optionally wrap in cached() with a short TTL.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0286. See audit/2026-05-31/full-codebase-audit.md.
