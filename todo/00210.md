# #00210 -- Subcommand-routing tests assert only the outer `route_subcommand` step, which fires for every subcommand - the

**Type:** refactor | **Priority:** Low

execute() in src/commands/gate/gateMain.ts wraps the entire switch in `withStep(ctx, 'route_subcommand', ...)`, so ctx.step is called with 'route_subcommand' for EVERY subcommand and group. The test 'routes to welcome preview subcommand' (and the comment claims it verifies welcome-preview routing) asserts `expect(ctx.step).toHaveBeenCalledWith('route_subcommand')`, which would pass for setup, reset, status, set-questions, or any other branch - it does not verify that the preview path specifically ran. It provides no protection against the preview branch being mis-wired. (Contrast with the status/config tests at 211-225, which assert branch-specific steps like 'query_stats'/'load_config' and are meaningful.)

**Location:** `tests/commands/gate/gateMain.test.ts:248-255`
**Category:** dead-code | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Assert a step or side-effect unique to executeWelcomePreview, e.g. spy on renderWelcomeTemplate and `expect(renderWelcomeTemplate).toHaveBeenCalled()`, or assert a preview-specific withStep phase ('render_preview').
