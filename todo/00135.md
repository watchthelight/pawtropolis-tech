# #00135 -- Skullmode clamp tests are vacuous (odds=0 coerced to 1000) and mock SKULLMODE_ODDS_MAX=10000 while production 

**Type:** bug | **Priority:** Medium

Same defect class as the dadmode test. 'clamps odds to minimum' (line 146-153) sets skullmode_odds: 0 and expects a react, but src/listeners/messageSkullMode.ts:44 does `Number(cfg.skullmode_odds || 1000)` so 0 becomes 1000 and the SKULLMODE_ODDS_MIN clamp (Math.max) is never exercised. 'clamps odds to maximum' (line 155-163) and 'does not react when roll is non-zero' (line 136-144) run against a MOCKED SKULLMODE_ODDS_MAX of 10000 (test line 27-30), but the real constant (src/lib/constants.ts:39) is SKULLMODE_ODDS_MAX = 1000 - a 10x divergence. The max-clamp behavior the test claims to verify (cap at 10000) is not what production does (cap at 1000). A change to the real bound would not be caught. Impact: false confidence; production odds bounds untested.

**Location:** `tests/listeners/messageSkullMode.test.ts:146-163`
**Category:** correctness | **Confidence:** high | **Audit severity:** medium (adversarially confirmed)

**Suggested fix:** Exercise the lower clamp with a value that is not falsy (e.g. 1 or a negative number). Stop mocking constants.js with non-production values; import the real bounds or assert the clamped odds explicitly so the test reflects SKULLMODE_ODDS_MAX=1000.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0223. See audit/2026-05-31/full-codebase-audit.md.
