# #00233 -- createMockInteraction clobbers the enriched member/user/guild mocks with the caller's raw partial via trailing

**Type:** bug | **Priority:** Low

The factory builds a full `user` (l274), `guild` (l275) and `member` (l276, which injects `roles`, `permissions`, `user`, `send`, `kick`, `ban`). It sets `user`/`member`/`guild` in the returned object (l280-282), but then spreads `...rest` again at l301. Because `rest` still contains the caller's original `user`/`guild`/`member` partials, those raw partials overwrite the enriched mocks. So `createMockInteraction({ member: { permissions: { has: () => true } } })` yields `interaction.member` === just `{ permissions: {...} }` - `member.roles`, `member.user`, `member.send`, etc. are now `undefined`. Note `guildId: guild.id` (l283) is computed before the clobber so it still points at the default guild id even when a custom `guild` partial without an `id` is supplied, producing an inconsistent interaction (guildId from default guild, guild object from the partial). Concrete impact: any test that overrides member/user/guild (e.g. tests/commands/stats/approvalRate.test.ts:109 `createMockInteraction({ member } as any)`) silently receives a degraded mock; code under test that reads member.roles.cache or member.user can hit undefined and either throw or take an unintended branch, making the test weaker/greener than it appears. Same pattern exists in createMockButtonInteraction (l315-339, `...overrides` at l338) and createMockModalInteraction (l353-380, `...rest` at l379).

**Location:** `tests/utils/discordMocks.ts:276-302`
**Category:** correctness | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Drop user/guild/member out of the trailing spread so the enriched objects win, e.g. destructure them out: `const { user: _u, guild: _g, member: _m, ...restNoEntities } = rest;` and spread `...restNoEntities`, OR merge instead of replace: build the return object then deep-merge only the remaining keys. Apply the same fix to the button and modal factories.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0229. See audit/2026-05-31/full-codebase-audit.md.
