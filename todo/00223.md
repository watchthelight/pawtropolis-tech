# #00223 -- mockTransaction has wrong shape vs better-sqlite3 / source usage; only unexercised because no test hits the in

**Type:** bug | **Priority:** Low

The hoisted mock is `mockTransaction: vi.fn((fn) => fn())`, which immediately INVOKES the callback and returns its (undefined) result. But the real `db.transaction(fn)` (better-sqlite3, see src/db/db.ts:96-98) returns a CALLABLE wrapper, and the source uses it as `db.transaction(() => {...})()` (threadReopen.ts:89-109). With this mock, `db.transaction(fn)` returns `undefined`, and the source's trailing `()` would call `undefined()` -> TypeError. The tests pass only because NONE of them exercise the successful within-7-days reopen branch (every success test uses a ticket closed >7 days ago, which returns at threadReopen.ts:79 before reaching the transaction; the 'error handling' test makes db.transaction throw synchronously before the trailing `()`). Net effect: the core reopen transaction logic (reopenTicket + open_modmail guard re-insert + addOpenThread + thread unarchive/unlock + applicant DM) at threadReopen.ts:87-149 is entirely untested, and the mock that exists would actually break if a test were added. Contrast with the sibling threadOpen.test.ts:16 which correctly uses `(fn) => fn`.

**Location:** `tests/features/modmail/threadReopen.test.ts:24`
**Category:** test-correctness | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Change the mock to `mockTransaction: vi.fn((fn: Function) => fn)` (return the function, matching better-sqlite3 and threadOpen.test.ts), then add a test for the happy path: a closed ticket within 7 days that asserts reopenTicket is called, the open_modmail UPSERT runs, addOpenThread is called with the thread_id, and the success message `Modmail thread reopened: <#...>` is returned.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0193. See audit/2026-05-31/full-codebase-audit.md.
