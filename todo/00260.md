# #00260 -- Actions workflows are red on main; get the commit check mark green

**Type:** chore | **Priority:** Medium

Every recent run on main fails, so the latest commit shows a red X instead of a check. Three separate workflows are involved and they do not share a root cause.

**Location:** `.github/workflows/ci.yml`, `.github/workflows/update-badges.yml`, `.github/workflows/refresh-discord-badges.yml`

**1. CI (`ci.yml`) fails at `npm ci`.** The committed `package-lock.json` is out of sync with `package.json`. The runner reports roughly twenty `npm error Missing: @esbuild/<platform>@0.28.2 from lock file` lines and exits 1 before any test runs.

Confirmed cause: the working tree already carries a regenerated lockfile that was never committed. `git show HEAD:package-lock.json | grep -c "@esbuild/freebsd-arm64"` returns 3, the working copy returns 6, and `git diff --stat package-lock.json` is 970 insertions / 922 deletions. The esbuild platform optional deps landed locally when vitest 4.1.7 or tsup pulled esbuild 0.28.2, and only the lockfile changed.

Fix: commit the regenerated `package-lock.json`. Verify with a clean `npm ci` locally first. This is a one-line commit and it turns CI green on its own.

**2. Update Badges (`update-badges.yml`) has failed on its schedule since at least 2026-08-28.** Fails within about 15 to 23 seconds, before doing real work. Failing-step output shows only checkout teardown, so the actual failure needs `gh run view <id> --log` rather than `--log-failed` to locate.

**3. Refresh Discord Badges (`refresh-discord-badges.yml`) also fails on schedule.** Pushes to `bot/discord-badges-refresh`. Likely shares a cause with 2 (both are badge jobs), but that is unverified.

Both badge workflows also emit: `Node.js 20 is deprecated. actions/checkout@v4, actions/setup-node@v4 are being forced to run on Node.js 24`. Worth bumping those to v5 in the same pass.

**Suggested order:** land the lockfile commit first, since it alone restores the check mark on new commits. Then work the two badge workflows, which are scheduled jobs and do not gate commit status.
