# #00192 -- Search-session storage is written every search but never read

**Type:** refactor | **Priority:** Low

storeSearchSession (line 359) is called on every search (index.ts:267) and generateNonce (line 352) mints a nonce embedded into the select-menu custom ID (components.ts:260). However getSearchSession (line 373) is never called anywhere in production code (only in tests/graphify artifacts). The search select-menu handler (index.ts:403-413) ignores the nonce/session entirely and simply acts on interaction.values[0]. The entire SEARCH_SESSIONS LRUCache, the nonce generation, and storeSearchSession are therefore dead weight - allocating crypto randomBytes and cache entries on every search for data that is never consumed.

**Location:** `src/commands/help/cache.ts:333-388`
**Category:** dead-code | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Either remove SEARCH_SESSIONS/generateNonce/storeSearchSession/getSearchSession (and simplify buildSearchComponents to not need a nonce), or actually use getSearchSession in handleHelpSelectMenu to validate/restore the search context. Pick one; right now it's wasted work and misleading API surface.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0046. See audit/2026-05-31/full-codebase-audit.md.
