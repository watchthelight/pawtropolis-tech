# #00208 -- Initial-check setTimeout is neither captured, cleared on stop, nor unref'd

**Type:** bug | **Priority:** Low

startDiskSpaceScheduler schedules the first disk check with `setTimeout(async () => {...}, 15000)` but does not store the returned handle. Only the periodic `setInterval` handle is saved to `_activeInterval` and unref'd. Consequences: (1) `stopDiskSpaceScheduler()` cannot cancel this pending timer, so if the bot starts and is asked to shut down within 15s, `checkDiskSpace` still fires after stop was called (touching `client.guilds.cache`, sending an embed) during teardown; (2) unlike the `setInterval`, this timeout is not `.unref()`'d, so for up to 15s it can keep the Node event loop alive and delay a clean process exit. Compare with badgeRefreshScheduler.ts which captures and unref's its startupTimer.

**Location:** `src/scheduler/diskSpaceScheduler.ts:236-244`
**Category:** leak | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Capture the timeout handle (e.g. a module-level `_startupTimeout`), call `.unref?.()` on it, and clear it in `stopDiskSpaceScheduler()` alongside `_activeInterval`.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0133. See audit/2026-05-31/full-codebase-audit.md.
