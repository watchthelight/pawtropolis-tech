# #00251 -- Add action_log(guild_id, action, ts) index for churn/cohort/pulse queries on large data.db

**Type:** perf | **Priority:** Medium

Fixing #00145 rewired the observatory daily metrics, cohort retention, and the pulse leave-spike / rapid-join-leave detectors to read from the append-only action_log table, filtering on action IN ('member_join','member_leave') with ts ranges and per-user latest-event window functions. action_log currently has an index on (guild_id, ts) but none on (guild_id, action, ts). On the observed ~5GB data.db these action-filtered aggregations and the rapid-join-leave correlated subquery scan more rows than necessary.

**Location:** `action_log` table schema / migrations; consumers in `src/features/statsObservatory/refresh.ts` and `src/queries/pulse.ts`
**Category:** performance (missing composite index)

**Suggested fix:** Add a migration creating `CREATE INDEX IF NOT EXISTS idx_action_log_guild_action_ts ON action_log(guild_id, action, ts)`. Confirm the churn/cohort/pulse queries use it (EXPLAIN QUERY PLAN) and that write overhead on join/leave logging stays acceptable.

**Evidence:** surfaced while implementing #00145 (rewire churn metrics to action_log). See commit referencing (#00145).
