# #00174 -- avatar_confirm18 modal route is dead infrastructure and has no handler (latent route-miss bug)

**Type:** refactor | **Priority:** Low

modalPatterns.ts defines MODAL_18_RE (/^v1:avatar:confirm18:code([0-9A-F]{6})$/), the ModalRoute union member { type: 'avatar_confirm18' }, and identifyModalRoute returns it (lines 149-152). However: (1) No code anywhere in src/web/scripts ever creates/shows a modal with customId 'v1:avatar:confirm18:' - grep finds the string only in modalPatterns.ts and interactionCreate.ts, never in a ModalBuilder/showModal call, so the route is unreachable in practice. (2) Even if such a modal were shown, the router in src/events/interactionCreate.ts handles gate_submit_page, review_reject/perm_reject/accept/kick/vote_out/unclaim, report_resolve, qotd_suggest, qotd_reject - but has NO branch for route.type === 'avatar_confirm18'. It would fall through to the catch-all at interactionCreate.ts:984-1000 and post an 'Unhandled modal' error card. So the union member is both dead and a latent bug.

**Location:** `src/lib/modalPatterns.ts:75,98,149-152`
**Category:** dead-code | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Either remove MODAL_18_RE, the 'avatar_confirm18' union member, its identifyModalRoute branch, and the '|| customId.startsWith("v1:avatar:confirm18:")' clause in interactionCreate.ts:769; or, if the 18+ avatar-source confirmation is intended to exist, wire the showModal producer AND add a matching route.type === 'avatar_confirm18' handler in the router.
