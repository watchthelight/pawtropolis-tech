# #00156 -- PRAGMA foreign_keys = OFF is a silent no-op inside the migration runner's transaction

**Type:** bug | **Priority:** Low

The migration runner (scripts/migrate.ts:209-213) wraps every migration in db.transaction(), so migrate010 always executes inside an open transaction. Migration 010 calls db.pragma("foreign_keys = OFF") at line 97 before the DROP/RENAME table rebuild and db.pragma("foreign_keys = ON") at line 119 after. Per SQLite semantics, PRAGMA foreign_keys is a no-op while a transaction is pending - it can only be toggled when no BEGIN/SAVEPOINT is active. Therefore the intended FK disable never happens; foreign-key enforcement stays ON throughout the table rebuild. The migration happens to still succeed because the only FK involved is guild_question -> guild_config (parent), which the copied rows satisfy, and nothing references guild_question as a parent. But the code's stated safety strategy ('disable foreign keys temporarily to rebuild the table') is silently defeated, and the final pragma at line 119 also does nothing, so FK state after the migration is whatever the runner set (ON), not something this code controls. If a future child table is added that references guild_question, the DROP at line 114 would fail unexpectedly because FKs are actually enforced.

**Location:** `migrations/010_limit_questions_to_5.ts:97-119`
**Category:** correctness | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Drop the foreign_keys pragma toggling here (it cannot work inside the runner transaction). For SQLite table rebuilds that truly need FKs off, use the documented 12-step procedure: toggle PRAGMA foreign_keys OUTSIDE any transaction (e.g. have the runner expose a non-transactional path) or use PRAGMA legacy_alter_table plus a foreign_key_check after rebuild. At minimum, remove the misleading OFF/ON calls and add a `PRAGMA foreign_key_check` after the rebuild to assert integrity.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0001. See audit/2026-05-31/full-codebase-audit.md.
