# #00268 -- Release 6.2.0: normalise production env, deploy runbook, post-deploy soak

**Type:** chore | **Priority:** High | **Status:** `WIP`

Ship the performance pass (#00277 to #00267) as 6.2.0 and fix the production configuration that currently defeats it.

**Found on the host (read-only probe, 2026-09-02):** `.env` has `LOG_LEVEL=trace`, `OPS_HEALTH_SCHEDULER_DISABLED=1`, `METRICS_SCHEDULER_DISABLED=1`, `SECURITY_AUDIT_SCHEDULER_DISABLED=1`, `BOT_LOCATION=local`, and the dead keys `NSFW_TAGGER_ENABLE`, `REMOTE_SSH`, `SSH_HOSTS`. `DB_HEALTHCHECK_MODE=quick` is already set. Trace logging in production is a CPU and disk cost on its own, and three schedulers the pass optimised are switched off, so mod metrics have not refreshed.

**Runbook**

1. Merge `perf/optimization-pass` into `main` fast-forward; bump `package.json` and `web/package.json` to 6.2.0; write the CHANGELOG section; commit `chore(release): 6.2.0`.
2. Over SSH, by key and without printing values: `LOG_LEVEL=info`, delete the three `*_SCHEDULER_DISABLED` lines, `BOT_LOCATION=ec2`, delete the three dead keys, add `SENTRY_PROFILES_SAMPLE_RATE=0`. Keep `.env.bak-6.2.0`.
3. Decide the backfill process (#00276) and prune backups by hand once (#00269) before deploying.
4. `./deploy.sh` with tests on. Then the VACUUM window: stop bot, web and litestream; `VACUUM`; start all three. Record `data.db` size before and after.
5. Soak: 30 minutes and 24 hours of `pm2 logs`, `pm2 jlist`, `/dashboard/system`; fill the table in #00277.
6. Day two: read the `retention` dry-run lines, then `RETENTION_ENABLED=true` and `pm2 restart pawtropolis`.

Rollback is `git revert` on `main` plus `./deploy.sh --fast`; the pre-deploy backup restores the database if a migration misbehaves (none pending).
