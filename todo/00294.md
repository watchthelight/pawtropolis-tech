# #00294 -- Drop the two unused indexes on messages_archive

**Type:** chore | **Priority:** Medium

Owner decision 11 (#00287), from PERF-7 and PERF-8 of the v26 audit.

Measured on the host on 2026-11-15, read-only: the database is 1,227 MB, 673 MB of tables and 555 MB of indexes. 22 indexes repeat the leading columns of another index on the same table, but together they take 7.8 MB, so they stay.

The weight is on `messages_archive`: `idx_msgarc_author_time` (105 MB) and `idx_msgarc_channel_time` (103 MB). No query in the bot, the dashboard or the scripts was found that filters that table by author or by channel. The report scripts in `scripts/report/` filter by guild, which is what `idx_msgarc_guild_time` (102 MB) is for, so that one stays.

Before anything is dropped:

- Run every query that touches `messages_archive` through the query planner and confirm that none picks either index.
- Time the insert of archived messages with and without the two indexes, on a copy of the database.

If both hold, a migration drops the two indexes and its notes say how to create them again. The file does not get smaller without a `VACUUM`; the freed pages are reused as the archive grows.
