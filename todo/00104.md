# #00104 -- INSERT catch block treats ALL errors as 'duplicate verification' and silently aborts

**Type:** bug | **Priority:** Medium

The try/catch around the INSERT (lines 195-203) assumes any thrown error means a UNIQUE-constraint duplicate and replies 'You're already verified!' then returns. But the same catch fires for unrelated failures: missing verified_users table (migration 064 not run), disk full / SQLITE_BUSY, corruption, etc. In those cases the user is falsely told they are already verified, no role is granted, and no log is written - a silent failure that masks the real DB error from operators (only logger.warn 'duplicate verification attempt' is emitted, with the actual err object buried). Genuine duplicates are also already prevented earlier by the existence check at line 61, so reaching this catch via a true duplicate requires the rare double-run race, making the misclassification of other errors the more likely real-world trigger.

**Location:** `src/commands/verify.ts:195-203`
**Category:** correctness | **Confidence:** high | **Audit severity:** medium (adversarially confirmed)

**Suggested fix:** Inspect the error: only treat it as a duplicate when err.code === 'SQLITE_CONSTRAINT_UNIQUE' (or the message contains 'UNIQUE constraint failed'); otherwise log at error level and tell the user verification failed and to try again later. Re-throw or surface unexpected errors instead of swallowing them as 'already verified'.
