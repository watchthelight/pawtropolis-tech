# #00045 -- Regenerate tests/fixtures/schema.sql from post-067 dump

**Type:** chore | **Priority:** Medium

`tests/fixtures/schema.sql` is the seed for the in-memory test DB. It was last regenerated before several migrations landed and is now drifting:

- `ticket` table is the pre-067 5-column shape (`app_id, guild_id, number, thread_id, created_at`). Migration 067 redefined it to a 16-column shape (`id, type_key, ...`). The dump still shows the old definition.
- `ticket_attachment`, `ticket_message`, `ticket_event`, `ticket_type`, `ticket_counter` are absent (all in migration 067).
- `channel_cache` is absent (migration 053).
- `config_audit_log` is absent (migration 060).
- Possibly more: full audit needed against migrations/ directory.

Tests work around these gaps via `tests/web/_helpers/db.ts` `MISSING_DDL` shims (channel_cache, config_audit_log, ticket_v067, ticket_attachment). The shim list is accumulating; better to regenerate the fixture once and drop the shims.

Action:
1. On EC2, run `sqlite3 data/data.db ".schema --indent" > tests/fixtures/schema.sql.new` (or whatever the existing dump tool is; see `scripts/` for the original tool that produced the current file).
2. Diff against the current `schema.sql` to verify ALL migrations are reflected.
3. Replace `tests/fixtures/schema.sql`.
4. Remove the four `MISSING_DDL` constants from `tests/web/_helpers/db.ts`.
5. Drop the `db.exec(MISSING_DDL...)` lines from `welcome.mentionables.test.ts`, `export.test.ts`, `tickets.attachments.test.ts`. Tests should pass without them.
6. Run full suite + typecheck to confirm no surprises.

**Evidence:** slice 4 found channel_cache + config_audit_log missing; slice 7 found stale `ticket` table.
