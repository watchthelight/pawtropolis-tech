# #00093 -- Ticket open button has no dedup/cooldown - double-click creates duplicate channels and burns numbers

**Type:** bug | **Priority:** Medium

handleOpenButton defers ephemerally then calls TicketService.create() with no per-user/per-type guard. TicketService.create() (src/features/tickets/service.ts:214-352) never checks for an existing open ticket of the same type for the opener - it unconditionally allocateNextNumber(), creates a Discord channel, posts a greeting with role pings, and inserts a ticket row. The interactionCreate router (src/events/interactionCreate.ts:582-595) routes tk: buttons directly to handleTicketButton with no checkCooldown wrapper (unlike error-card buttons which do gate on a cooldown). Discord button double-clicks are extremely common, and because the first interaction is deferred (not yet replied) the second click is still a valid, separately-dispatched interaction. Two near-simultaneous clicks each create a full ticket channel, each consume a ticket number, and each fire pingRoleIds notifications. Impact: orphan/duplicate ticket channels, wasted ticket numbers, duplicate staff pings, and user confusion about which channel is real.

**Location:** `src/features/tickets/handlers.ts:215-257`
**Category:** race | **Confidence:** high | **Audit severity:** medium (adversarially confirmed)

**Suggested fix:** Add a guard before creation: either (a) a short per-(userId, typeKey) cooldown via checkCooldown around handleOpenButton, and/or (b) in TicketService.create(), SELECT for an existing open ticket WHERE opener_user_id = ? AND type_key = ? AND status = 'open' and short-circuit (reply with a link to the existing channel) instead of opening another. A UNIQUE partial index on (opener_user_id, type_key) WHERE status='open' would make it race-proof.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0113. See audit/2026-05-31/full-codebase-audit.md.
