# #00202 -- closed_at parsed as local time but stored as UTC, skewing the 7-day reopen window

**Type:** bug | **Priority:** Low

closeTicket writes `closed_at = datetime('now')` (tickets.ts:164-166), which SQLite stores as a space-separated UTC string like '2026-05-31 12:34:56' (TEXT column, src/db/db.ts:186-187). reopenModmailThread computes `const closedAt = new Date(ticket.closed_at).getTime()` (line 73). Per the ES spec, the date+time space-separated form (no 'T', no 'Z') is parsed as LOCAL time by V8, not UTC (verified: new Date('2026-05-31 12:34:56') yields a local-time instant, off by the host UTC offset). So closedAt is shifted by the server's UTC offset (e.g. several hours), making the `now - closedAt > sevenDays` boundary (lines 75-77) decide reopen-vs-new-thread incorrectly near the 7-day edge. Low impact (hours of skew on a 7-day window) but a real correctness defect.

**Location:** `src/features/modmail/threadReopen.ts:73-85`
**Category:** correctness | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Parse explicitly as UTC: `new Date(ticket.closed_at.replace(' ', 'T') + 'Z').getTime()`, or store/compare epoch seconds consistently. Best: use a shared dt helper that knows the SQLite storage format.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0094. See audit/2026-05-31/full-codebase-audit.md.
