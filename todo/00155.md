# #00155 -- Alternate `--fresh` deploy path runs `npm ci` (with devDependencies) on the production host

**Type:** chore | **Priority:** Medium

The hardened canonical deploy (deploy.sh:341, 421, 428) correctly installs prod deps with `npm ci --omit=dev`. But the alternate remote-fresh deploy paths in scripts/start.sh:700 (`ssh ... 'cd ${REMOTE_PATH} && tar -xzf deploy.tar.gz && npm ci'`) and scripts/start.cmd:656 (identical) run plain `npm ci`, which installs the FULL devDependency tree on prod: eslint, @typescript-eslint/*, vitest, @vitest/*, tsup, tsx, prettier, @anthropic-ai/sdk, pino-pretty, etc. (package.json:76-93). Every one of those plus their transitive deps gets installed and may execute install lifecycle scripts on the production host, substantially enlarging the supply-chain attack surface for no runtime benefit (the bot runs from prebuilt dist/ via ecosystem.config.cjs and does not need the dev toolchain). The inconsistency also means dependency provisioning differs depending on which deploy entrypoint the operator uses.

**Location:** `scripts/start.sh:700 (and scripts/start.cmd:656)`
**Category:** Dependency / supply-chain | **Confidence:** high | **Audit severity:** medium (adversarially confirmed)

**Suggested fix:** Change both start.sh:700 and start.cmd:656 to `npm ci --omit=dev` to match deploy.sh, or deprecate these legacy fresh-deploy paths in favor of the hardened deploy.sh so there is a single, consistent install command on prod.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0360. See audit/2026-05-31/full-codebase-audit.md.
