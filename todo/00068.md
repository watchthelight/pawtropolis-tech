# #00068 -- PM2 self-stop kills the process mid-restore, so file replacement/verify/restart never run

**Type:** bug | **Priority:** High

restoreCandidate with pm2Coord=true runs `await execAsync('pm2 stop ' + processName)` (line 506) BEFORE replacing the DB file (line 544) and before restarting PM2 (line 620). The live restore button (src/features/dbRecoveryButtons.ts:193-199) invokes this path with pm2Coord:true and the bot itself is the PM2-managed process (env.PM2_PROCESS_NAME). When PM2 stops that very process, the running Node event loop is terminated, so the awaited execAsync never resolves and steps 4-6 (copyFile of the candidate over the live DB, post-restore verification, `pm2 start`) never execute. Result: the database is NOT restored, PM2 may leave the app stopped, and the Discord reply promising success is never sent. The pre-restore backup is created (step 2) but the actual restore silently no-ops.

**Location:** `src/features/dbRecovery.ts:489-559`
**Category:** correctness | **Confidence:** medium | **Audit severity:** high (adversarially confirmed)

**Suggested fix:** Do not stop the running bot from within itself. Either (a) perform the copy + integrity verify FIRST while running, then schedule a detached `pm2 restart` (spawned with detached:true / unref) as the final step, or (b) move restore into an out-of-process CLI/worker (src/ops/dbRecoverCli.ts) that PM2 does not manage, or (c) use better-sqlite3's online backup API to replace data without stopping the process.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0072. See audit/2026-05-31/full-codebase-audit.md.
