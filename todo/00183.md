# #00183 -- `--limit` with a missing value yields NaN and the per-run limit is silently ignored

**Type:** bug | **Priority:** Low

`const LIMIT = limitArg >= 0 ? parseInt(args[limitArg + 1], 10) : Infinity;` When `--limit` is passed as the final argument with no following value, `args[limitArg+1]` is undefined and `parseInt(undefined,10)` is NaN. Later `if (runAdded >= LIMIT)` (line 153) is `runAdded >= NaN`, which is always false, so the intended smoke-test cap never triggers and the script pages the entire #general history instead of stopping. Not data-corrupting (INSERT OR IGNORE), but defeats the documented `--limit 500` smoke-test mode and can run far longer / hit far more Discord API than the operator intended.

**Location:** `scripts/backfill-general.mjs:30-31, 153-156`
**Category:** correctness | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Validate the parsed value: `const n = parseInt(args[limitArg+1], 10); const LIMIT = Number.isFinite(n) && n > 0 ? n : Infinity;` and error out (or warn) if `--limit` is present but the value is missing/NaN.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0011. See audit/2026-05-31/full-codebase-audit.md.
