# #00031 -- Default BACKUP_BEFORE_DEPLOY to 1 in deploy.sh

**Type:** chore | **Priority:** Medium

deploy.sh has optional pre-deploy DB backup behind BACKUP_BEFORE_DEPLOY env var, defaulting to 0. Production deploys should always back up the DB before migrations. Current practice relies on manual backup commands or Litestream replication.

Action:
1. Change default in deploy.sh from 0 to 1.
2. Document override in help text: "Database backed up automatically; override with BACKUP_BEFORE_DEPLOY=0".
3. Test: deploy with default; verify data/backups/data.db.<timestamp> is created.
4. Add the backup directory to the rsync exclude list so future deploys do not push backups to prod.

**Evidence:** audit/2026-05-19/deps-ops-findings.md (Finding 17)
