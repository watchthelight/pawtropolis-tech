# #00256 -- Live presence (Currently Online / In Voice Now) is bundled into the 60s range-keyed pulse cache

**Type:** bug | **Priority:** Low

getGuildSnapshot(guildId) (online_count, voice_users_now) is real-time presence that does not depend on the selected time window, but it is computed inside the same cached(guildKey, CACHE_TTL.medium=60_000, ...) object whose key is rangeCacheKeyParts(range,60). Consequences: (1) the UI labels these cards 'live from Discord' / 'connected to voice', yet they are stale by up to ~60s and only refresh when the minute bucket rolls or the user changes the window; (2) switching the time window pointlessly recomputes the snapshot since it shares the range-scoped key. This is a correctness/accuracy mismatch between the 'live' presentation and the caching.

**Location:** `web/src/routes/dashboard/pulse/+page.server.ts:37-45; consumed at web/src/routes/dashboard/pulse/+page.svelte:257-288 (guildSnapshot 'live from Discord')`
**Category:** caching / staleness | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Pull getGuildSnapshot out of the range-keyed bundle and cache it under a window-independent key with a short TTL (e.g. CACHE_TTL.short or no cache), keyed only by guildId, so presence reflects near-real-time state regardless of the selected window.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0350. See audit/2026-05-31/full-codebase-audit.md.
