# #00231 -- "uses default rate when not specified" test cannot detect a broken default sample rate

**Type:** bug | **Priority:** Low

The test deletes WIDE_EVENT_SAMPLE_RATE to exercise the DEFAULT_SAMPLE_RATE (0.1) path, but it asserts using an outcome:"error" event. In wideEventEmitter.ts shouldSample() returns true for errors/timeouts BEFORE getSampleRate() is ever consulted (lines 104-105). So logger.error is called regardless of what the default rate is. The test would still pass if DEFAULT_SAMPLE_RATE were 0, or if getSampleRate() returned garbage, or if the default-rate branch were deleted entirely. It provides false confidence that the default sampling behavior is covered. Impact: a regression that breaks default sampling of success events (the actual purpose of the default) would not be caught here.

**Location:** `tests/lib/wideEventEmitter.test.ts:188-206`
**Category:** test-integrity | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Use a success event and assert sampling behavior deterministically. Since sampling is hashTraceId(traceId) < rate, pick a traceId whose hash is below/above 0.1 and assert logger.info is/ isn't called; or stub Math via a known traceId. At minimum test a success outcome rather than an error so the default-rate code path is actually reached.

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0216. See audit/2026-05-31/full-codebase-audit.md.
