# #00263 -- Perf pass T1: per-message and per-interaction hot path

**Type:** refactor | **Priority:** High | **Status:** `WIP`

Second tier of the performance plan. Lands after #00262.

**Items**

1. Central prepared-statement cache in `src/db/db.ts` and `web/src/lib/server/db.ts` (514 `db.prepare` call sites compile SQL per call today). Statements from `db.prepare` become shared: never call `.pluck/.raw/.expand/.safeIntegers` on them.
2. `src/events/messageCreate.ts`: static imports instead of `await import()` per message; in-memory guards (`isOpenModmailThread`, open verify-thread set) before DB lookups on thread messages. Same in `src/features/modmail/routing.ts` and `src/lib/cmdWrap.ts`.
3. `isReviewer` / `hasStaffPermissions` read reviewer config from the `getConfig` cache instead of a raw SELECT per interaction; debug-object construction gated on log level.
4. activityTracker first-message LRU; ticket transcript open-channel set.
5. Short-code lookup: no `sqlite_master` probe per click, mapping written at application creation, draft collision check via the indexed mapping table.
6. Review card rendered once per approval; static `EmbedBuilder` imports in review flows.
7. Scan pipeline waits on an event instead of polling the DB every 200 ms.
8. Banner attachment read once at module init.
9. Modmail thread permission edits skipped when already granted; staff member set built in one pass.
10. Invite tracker upserts only changed invites; leave classification uses one audit-log fetch.
11. Hoisted per-event allocations (wide event sampling, action meta map, Sentry ignore lists, inventory catalog memo).
