# #00189 -- Health-check timeout timer is never cleared and not unref'd, keeping a 5s timer + closure alive after every /h

**Type:** bug | **Priority:** Low

timeoutPromise creates setTimeout(...HEALTH_CHECK_TIMEOUT_MS=5000) but the handle is never stored or cleared. In the normal fast path healthCheckPromise wins Promise.race, yet the 5s timer keeps running to completion on every single /health invocation, holding the reject closure (and the rejected Error it constructs) alive. Unlike armWatchdog in cmdWrap.ts (which calls timer.unref()), this timer is not unref'd, so it can also delay graceful process shutdown by up to 5s. It is not a correctness bug in the happy path (the late rejection is still consumed by Promise.race so no unhandled rejection), but it is an avoidable per-call resource/lifecycle leak in a command anyone can spam.

**Location:** `src/commands/health.ts:218-235`
**Category:** leak | **Confidence:** high | **Audit severity:** low (adversarially confirmed)

**Suggested fix:** Capture the handle and clear it in a finally: `let t: NodeJS.Timeout; const timeoutPromise = new Promise<never>((_, reject) => { t = setTimeout(() => reject(new Error('Health check timeout')), HEALTH_CHECK_TIMEOUT_MS); }); try { await Promise.race([...]); } finally { clearTimeout(t!); }` and/or call t.unref().

**Evidence:** full-codebase multi-agent audit 2026-05-31, finding A0038. See audit/2026-05-31/full-codebase-audit.md.
