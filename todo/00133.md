# #00133 -- "returns a copy" tests pass trivially and miss the real shallow-copy aliasing bug in getSchedulerHealth

**Type:** bug | **Priority:** Medium

getSchedulerHealth() returns `new Map(schedulerHealth)` (schedulerHealth.ts:114) which is a SHALLOW copy: the SchedulerHealth value objects are the SAME references stored internally. recordSchedulerRun mutates those objects in place (lines 73-83: health.lastRunAt = now; health.consecutiveFailures++ etc.). Therefore a caller holding a result from getSchedulerHealth() will see its objects mutate out from under it on the next scheduler run, and could even corrupt internal state by writing to them. getSchedulerHealthByName, by contrast, returns a spread copy ({ ...health }, line 132), so the two accessors are inconsistent. The test "returns a copy of the internal map" only checks `health1 !== health2`, which is trivially true for any `new Map()` and does NOT detect the value-object aliasing. The timestamp-preservation tests (246-266) also re-read via getSchedulerHealthByName (which copies) so they never exercise the aliased map. Impact: the unit tests give false assurance that getSchedulerHealth returns an isolated snapshot; the underlying aliasing/shared-mutable-state defect is real but uncaught.

**Location:** `tests/lib/schedulerHealth.test.ts:163-170, 246-266`
**Category:** test-integrity | **Confidence:** high | **Audit severity:** medium (adversarially confirmed)

**Suggested fix:** In schedulerHealth.ts make getSchedulerHealth() deep-copy the values: `return new Map(Array.from(schedulerHealth, ([k, v]) => [k, { ...v }]));`. Then strengthen the test to capture a value object from getSchedulerHealth(), call recordSchedulerRun again, and assert the previously captured object did NOT change (e.g., totalRuns stayed the same).
