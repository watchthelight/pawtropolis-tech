# #00259 -- Remove Claude from the GitHub contributors panel

**Type:** chore | **Priority:** Low

The repo sidebar lists four contributors: watchthelight, pawtropolis-tech-bot, Werew0lfYeen, and claude. Only the first and third are real. The project convention is that all work commits as `watchthelight <admin@watchthelight.org>` with no `Co-Authored-By: Claude` trailer, so neither bot should appear.

**Location:** GitHub repo sidebar (Contributors panel), github.com/watchthelight/pawtropolis-tech

**What was verified:**

- `git log --all --format='%ae|%an'` across every ref (main plus `origin/bot/discord-badges-refresh`) returns exactly four authors: `admin@watchthelight.org`, `167818006+watchthelight@users.noreply.github.com`, `samboland@users.noreply.github.com`, `coffeedogstudioz@gmail.com`. No claude or bot author anywhere.
- Zero `Co-authored-by:` trailers naming Claude across all history. The only trailer present names watchthelight.
- `GET /repos/watchthelight/pawtropolis-tech/contributors?anon=1` returns three entries: watchthelight (1318), samboland (6), Werew0lfYeen (1). Neither `claude` nor `pawtropolis-tech-bot` is in the API response.

So the git history is already clean. The sidebar and the API disagree, which points at a stale GitHub-side association rather than anything fixable with a commit. No history rewrite is warranted, and none should be attempted: force-pushing 1325 commits to correct a display cache is the wrong trade.

**Suggested fix:** Confirm the sidebar still shows the extra entries after a cache-busting load. If it does, the likely cause is commits pushed by those App accounts to a branch that was later deleted, with GitHub retaining the association. Open a GitHub Support ticket asking them to recompute repo contributors. If the entries are stale App installs, revoking the Claude and pawtropolis-tech-bot GitHub App installations on this repo may also clear them.

**Blocks:** nothing.
